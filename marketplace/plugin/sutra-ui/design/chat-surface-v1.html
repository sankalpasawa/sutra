Chat surface — design v1

Three additions to the panel's existing turn, drawn entirely in this app's own design system: this page links static/panel.css rather than declaring tokens, so every colour and font below is the app's. Nothing in the app's information architecture moves — the rail, the panes and the composer are untouched.

1 · Governance chip — the filing chip, made expandable

The panel already files a turn and shows it as .fchip. Today the rest of the governance — routing, depth, flow, blueprint, trace — arrives as ~25 lines of machine voice inside the reply text. This keeps the chip as the only thing on screen and moves that content behind it. Click to expand; collapsed is the default and every turn.

2 · Thinking — the run strip, made openable

The app's .runstrip already says a turn is in flight, with an indeterminate sweep. The one thing it cannot answer is "what is it doing right now". This makes the strip clickable and drops the live log underneath it. The strip, its sweep and its reduced-motion handling are reused verbatim — only the log is new.

3 · Live workers — filling the app's own agents_live gap

The subagents fold already reads agent transcripts from disk and renders them through the same transcriptTurns() as the main thread — so drill-down already exists and is not being replaced. What it cannot show is the turn in progress: the fold is per-session and post-hoc. These rows are turn-scoped and live, and clicking one opens the agent that the fold already knows how to render. s.agents_live is the app's own hook for exactly this.
