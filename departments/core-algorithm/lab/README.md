An edit version can correct both lines, and with them this limit. 0.9.0 (Core Algorithm program, 2026-11-13) makes a step that cannot run, or fails, an outcome instead of an error. Until 0.8.0 a handler, the gate or a kind's settle hook that raised in the middle of a plan ended the run with an exception: the steps before it stayed done and paid, the journal got no row, and a second goal never ran. Now (1) the whole step runs guarded, from finding its method to paying for it: whatever the gate finds and whatever the handler raises (any `Exception`) or returns, the step ends as a receipt or as one `STEP_STOPPED` line in the run's hash chain, with the step, a reason and what the step's effect reads (`UNKNOWN` when it cannot be read); nothing after it runs; the run returns status `STEP_STOPPED` (work state `stopped`) with what ran and what it cost, the stopped step and the rest of the plan under `pending`, and `stopped` naming the step and the reason; the journal gets its row, the kinds settle their books, and the next goal runs; (2) a step is paid, in full or not at all, after its receipt is in the record, so a stopped step is never paid and the budget and the provider slots equal the start less the cost of the receipts; (3) what a handler returns is rebuilt as plain data like everything else that is handed in (an object, at most 16 levels), so no code of the handler runs after it returned; a return that is not plain data, or that sets one of the receipt's own fields (`method`, `scope`, `action`, `status`, `sha256`), stops the step; (4) a reason is a phrase from a closed list: `Gate changed before effect: <gate words>`, `Prerequisite not true before effect: <facts>`, `Handler refused: <the handler's own words>` when the handler raised the kernel's `Stop` with one text, `Handler failed: <the error's class>` for any other error (a `RuntimeError` too: Python raises those itself), `Handler returned what cannot be a receipt`, and `Kernel fault: <the error's class>` for an error of the kernel's own code inside the guard; a class is named by the name Python holds for it, read from the type itself so that no code of the class runs, and only when that name is plain (exact text of ASCII letters, digits and underscores that does not start with a digit): any other name is worded `unreadable`; of an error that is not such a refusal the kernel records the name of its class and nothing else (never its message), and it escapes what UTF-8 cannot carry in a handler's words, so the same stop has the same trace root on every machine that runs the same Python version, as long as the handler words its refusal the same way (the words after `Handler refused:` are the handler's own, as a receipt's detail is; a class's name is the running Python's, and Python renames classes between versions: `socket.timeout` is named `timeout` before 3.10 and `TimeoutError` from 3.10 on, so two records of one failure compare only on one Python version); (5) a kind whose settle fails is one `SETTLE_STOPPED` line and is named under `unsettled`, and the other kinds still settle. ### Structure

- `kernel/core.py`: bounded recursive resolver and safe local action boundary; since 0.4.0 it carries no learning, since 0.7.0 only the `simulate_fact` effect and a registry for the rest.
- `extensions/asks.py`: the `ask` action kind with its hooks, `answer` (the stamp) and `open_asks` (since 0.8.0).
- `extensions/constructor.py`: the `compile_candidate` and `emit_artifact` action handlers (out of the kernel since 0.7.0).
- `scenarios/`: authored, reviewed-in-fixture JSON packs.
- `extensions/knowledge.py`, `reflection.py` (with `Learner`, the per-run candidate-only learning since 0.4.0), `j2_projection.py`: bounded proposal utilities, **not** true external data/model/J2 integration.
- `extensions/standards.py`: the evidence adapter: a checklist over a workflow JSON becomes verified evidence rows (source = the adapter, version = the digest of what was checked); it runs when packs are authored, never inside the kernel.
- `extensions/implementation.py`: the implementation generator: from a plan and its state, a workflow in the `sutra-native` user-kit shape, its atoms, the owning department's scaffold and a page; PROPOSED_ONLY, deterministic, writes nothing, runs nothing.
- `tools/`: fixture, run and static-viewer scripts.
- `qa/`: independent verifier (does not import kernel), optional browser tests.
- `tests/`: regression and negative tests.
- `cases/`, `tools/packs/`, `tools/scenes/`, `kinds/`, `qa/checks/` and what later versions put into `extensions/` and `tests/`: the files of versions that only add; `added.json` is the book of them (every file by sha256) and of what the lab had recorded before (see "Additive versions" above).
- `release/baseline_v0_1_core.py`: historic experimental v0.1 reference fixture used by unit/trace verifier, not frozen historical Sutra Core v0.2.2.

### Do not claim

This test uses toy resource units, human-authored domain rules, simulated effect receipts and seeded candidate components. It does not move inventory, send a message, deploy an app, generate unknown code independently or allow itself to approve any release.
