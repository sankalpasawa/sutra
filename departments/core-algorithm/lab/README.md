a plan is admitted and priced at its full cost, also for steps that will be skipped at their turn, so a goal can stop as `RESOURCE_REQUIRED` for a budget it would not use; a constructor spec is not shape-checked when its pack is applied, so a malformed one stops the run at that step; `apply` copies the whole State for its trial, so its cost grows with the journal, and the State's fields are new objects after every `apply`; a generated workflow words every step the owner approves with the runtime's word ("the owner stamps the ask"), next to steps of kind `ask`; waiting costs nothing and never expires, so a wait can hold back a dearer plan that is ready; a goal that waits runs none of its other pending steps; a rule for a fact shadows every method for it, asks included; the gate reads stored evidence only (since 0.9.0 a step it refuses is recorded as stopped: see the limits of 0.9.0 above); a question's books are settled only by executed runs in its scope, never by a dry look; simulated effects still carry one constant version, so an effect made on a prerequisite reads valid again when that prerequisite is made again (unchanged from 0.7.0); two States with the same packs and the same journal issue the same receipt; amounts are bounded one by one (an integer of at most 4300 digits) but their sums are not, so a plan whose costs add up to more digits cannot be written down on a Python that limits the text of an integer; the flag `execute` is read as it is given, more than once in a run, so it must be exactly true or false; a version named inside `depends_on` is not checked, so a dependency on a version that is true, a list or an object is stored and can never be valid (0.9.0 removed these three: see its passage above); chains hundreds of rows long exhaust Python's recursion in `fact` and `on_event` (since 0.9.0 a chain that uses up the stack inside a step is that step's recorded stop: see the limits of 0.9.0 above). 0.7.0 was the second shrink version (move-outs M2 and M3): the kernel gets one generic primitive, an action-handler registry, keeps the gate (re-admission, prerequisites true, cost, provider slot, the receipt's own fields, the log) and gives up the effect; ### Structure

- `kernel/core.py`: bounded recursive resolver and safe local action boundary; since 0.4.0 it carries no learning, since 0.7.0 only the `simulate_fact` effect and a registry for the rest.
- `extensions/asks.py`: the `ask` action kind with its hooks, `answer` (the stamp) and `open_asks` (since 0.8.0).
- `extensions/constructor.py`: the `compile_candidate` and `emit_artifact` action handlers (out of the kernel since 0.7.0).
- `scenarios/`: authored, reviewed-in-fixture JSON packs.
- `extensions/knowledge.py`, `reflection.py` (with `Learner`, the per-run candidate-only learning since 0.4.0), `j2_projection.py`: bounded proposal utilities, **not** true external data/model/J2 integration.
- `extensions/standards.py`: the evidence adapter: a checklist over a workflow JSON becomes verified evidence rows (source = the adapter, version = the digest of what was checked); it runs when packs are authored, never inside the kernel.
- `extensions/implementation.py`: the implementation generator: from a plan and its state, a workflow in the `sutra-native` user-kit shape, its atoms, the owning department's scaffold and a page; PROPOSED_ONLY, deterministic, writes nothing, runs nothing.
- `tools/`: fixture, run and static-viewer scripts.
- `qa/`: independent verifier (does not import kernel), optional browser tests.
- `tests/`: regression and negative tests.
- `cases/`, `tools/packs/`, `tools/scenes/`, `kinds/`, `qa/checks/` and what later versions put into `extensions/` and `tests/`: the files of versions that only add; `added.json` is the book of them (every file by sha256) and of what the lab had recorded before (see "Additive versions" above).
- `release/baseline_v0_1_core.py`: historic experimental v0.1 reference fixture used by unit/trace verifier, not frozen historical Sutra Core v0.2.2.
