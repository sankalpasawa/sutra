BUILDERS WORK WITH TOOLS: every builder reads, writes and edits files in the run's output folder, runs commands there, and can search and fetch the web. Plan what the brief needs, not what a fixed format allows.
MISSING CAPABILITIES: when the work needs something no builder tool gives (a file converter, a parser, a chart or image generator, a client for an outside service), plan a workflow before the ones that need it whose atom builds it as a small script in the output folder, with its own test: its expected_output names the script and the test as files, and its verification checks that both exist and, when the form runs tests, that the test passes. Name the script in the how of every later workflow that uses it. It stays in the run's output as an artifact, so a later run can reuse it.
