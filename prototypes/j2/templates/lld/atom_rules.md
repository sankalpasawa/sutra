
WORK ATOMS: every workflow, fixes included, carries atoms: exactly one work atom for now, id "a1" (code renames it W-n.a1 at registration). goal: what must be true when it is done, one sentence. constraints: short strings, what must never break. context: references only, charter item numbers and section ids, never copied text. how: {kind: "AI" or "code", agent: who builds it, steps: which "## <Section>" it writes}. expected_output: written now, before any build: a short list of the concrete things that must exist in the LLD when the atom is done, each {text: the thing in plain words, kind, target}: heading (target: the section heading text, no # characters), ids (target: the id prefix, "R" for requirement ids R1, R2, ...), facts (target: a list of strings copied exactly from the charter or the Requester's answers). Code turns each item into a check and reports it met or not met; an item no check can verify, or an empty list, is rejected. verification: the checks code runs on the LLD after the builder writes it (the builder gets 3 attempts), each {text: the check in plain words, type, target, expect}. Only these types: heading-present (target: the section heading text only, with no # characters, e.g. "Problem"; expect true); section-not-empty (target: the heading text only, no # characters; expect: the minimum number of words); ids-unique (target: an id prefix, "R" for R1, R2, ...; expect true); facts-present (target: a list of strings that must all appear in the document; expect true). No browser checks. Each facts-present string is copied exactly from the charter or the Requester's answers (no invented facts). A goal that names a number needs a facts-present check. A workflow whose atom breaks a rule or lacks a field is rejected.
