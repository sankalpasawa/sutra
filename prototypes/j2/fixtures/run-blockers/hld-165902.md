# the agent

## Purpose and scope

the agent is a helper for about ten team leads and the Requester (company lead) at one company. It watches the team message lists for messages threads that have gone quiet on the team's side, tells urgent threads from ones that can wait, and quietly reminds the one team lead who owns each thread on chat. It also helps get threads closed on chat and tells the Requester when someone keeps ignoring reminders. The problem it addresses: important messages go unanswered, and last month a candidate's data-access request sat for 25 days before anyone saw it.

The success measure is that no important messages waits longer than 3 days for a reply, checked daily. the agent runs on its own every morning, and all reminders go through chat.

Shadow mode is a hard constraint. Nothing is sent on the company's behalf until the agent has run in shadow mode and the Requester has seen it work. In shadow mode, no chat reminder reaches any team lead.

Assumption: the quiet period, the definitions of important, urgent and can-wait, the rule for who owns a thread, the per-thread cap, the minimum gap between reminders, the daily limit per team lead and the ignore threshold take the values in the PRD Assumption lines. This HLD does not restate or change them.

## Components

- **C1** Inbox Reader: reads the team message lists each morning and lists the messages threads whose last message is from outside the team and that nobody on the team has replied to for the quiet period. Page P2. Covers R1.
- **C2** Thread Labeller: labels each quiet thread urgent or can-wait using the PRD definitions and records the reason for the label so people can read why. Pages P1, P2. Covers R2.
- **C3** Reminder Orderer: puts urgent quiet threads ahead of can-wait threads so reminders go out in that order within the same morning run. Page P1. Covers R3.
- **C4** Owner Resolver: finds the one team lead who owns each quiet thread under the PRD rule for who owns a thread, so the reminder goes to that person and not to the whole team. Page P1. Covers R4.
- **C5** Reminder Limiter: stops pestering by blocking a second reminder on the same thread to the same team lead in one run, skipping threads replied to or closed since the last run, and applying the per-thread cap, minimum gap and daily limit per team lead. Page P1. Covers R5.
- **C6** chat Reminder Sender: builds the chat reminder that names the thread and offers reply and close actions, records a close made on chat, and stops reminding about a closed thread. Page P1. Covers R6.
- **C7** Ignore Tracker: counts reminders on the same thread with no reply and no close, and when the ignore threshold is reached produces one report per thread naming the team lead and the thread for the Requester. Page P2. Covers R7.
- **C8** Morning Scheduler: starts the whole run on its own every morning without anyone launching it. Pages P1, P2. Covers R8.
- **C9** Shadow-Mode Gate: holds back every chat reminder to team leads until the Requester has seen the agent work, and instead records each would-have-sent reminder with the team lead and the urgent or can-wait label. Page P2. Covers R9.
- **C10** Daily Reporter: builds and posts the single daily chat report for the Requester once at the end of each run, covering the 3 days check, the would-have-sent reminders in shadow mode and the ignore-threshold reports. Page P2. Covers R10.

Requirement traceability, one line per PRD requirement:

- **R1** Quiet threads found in the message lists every morning: covered by C1.
- **R2** Urgent or can-wait label with a recorded reason: covered by C2.
- **R3** Urgent threads reminded before can-wait threads in the same run: covered by C3.
- **R4** Reminder goes to the one owning team lead, not the whole team: covered by C4.
- **R5** No pestering, with the per-thread cap, minimum gap and daily limit: covered by C5.
- **R6** Reminder names the thread and offers reply and close on chat, and a closed thread is no longer reminded: covered by C6.
- **R7** Ignore-threshold report to the Requester, once per thread: covered by C7, and included in the daily report by C10.
- **R8** Run starts on its own every morning: covered by C8.
- **R9** Shadow mode, with would-have-sent reminders in the daily report: covered by C9, and listed in the daily report by C10.
- **R10** One daily chat report for the Requester, combining the 3 days check, would-have-sent reminders and ignore-threshold reports: covered by C10.

Assumption: the words Gate, Labeller, Limiter, Orderer, Owner, Reader, Reporter, Resolver, Scheduler, Sender and Tracker in the component names are labels chosen by this design, not facts from the brief.
