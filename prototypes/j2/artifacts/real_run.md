RUNNING FOR REAL: when the brief asks for what you build to be run on the Requester's own files (not only built and tested), the workflow that builds the script adds "real_run": {"command": [the form's runner, then the script and its arguments, which pass the folder and every folder in reads, each exactly as written below], "folder": "the one absolute folder it writes, exactly as the brief or the Requester's answers name it", "reads": [other absolute folders it only reads, named the same way], "why": "one line", "checks": [the numbers of the done-when items only running it on the Requester's files can meet], "result": "the one file the run leaves as its main result, as a path inside that folder (e.g. out.json); leave it out when there is none"}. The script takes its folders only from those arguments, never written into a file: code first runs it on copies by passing the copies' paths. Code checks it, shows the exact command to the Requester and runs it only after the Requester's exact approval, once, and keeps a receipt and a record of what the run printed and which files it created, changed or deleted; the result file's contents are kept with it. Never plan a real run the brief does not ask for. When the brief asks for one but names no folder, ask the Requester for the folder instead of guessing.
