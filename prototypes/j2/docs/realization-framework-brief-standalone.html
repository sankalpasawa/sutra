J2 · Adaptation · Realization axis · 25 Oct 2026

Realization makes the full scope of the task explicit and checks it before J2 spends build credits.

This page describes the realization framework that runs in J2 now, on branch certainty-axis with J2_REALIZATION=1.

Situation

A brief gives J2 a goal. J2 cuts the goal into workflows and builds them.

Complication

A brief does not state all of its needs. A need found after the build needs a fix round. A fix round costs more than a plan change.

Resolution

Before the build, Realization finds the needs, gives each need an owner, and puts each piece of work in the correct type.

First principles

1

You can build only the needs that you know about.

So, list all needs, including the needs that the brief does not state.

2

Each type of thinking needs its own owner.

So, put each type of thinking in a different stage.

3

A decision costs less than a rebuild.

So, decide before you build.

4

A planner cannot check its own plan.

So, a separate judge and code do the check.

Procedure

1

Factors

List each item that changes the output. Give its source: brief (with a quote), general knowledge, research or budget.

OutputFactor list

2

Stages

Put the factors into stages. Each stage has one type of thinking, a goal, a method and a done-test.

Output1 to 8 stages: business, compliance, product, design, engineering, build, operations, growth

3

Workflows

Divide each stage into workflows. A workflow that delivers no done-when item is decide. A workflow that delivers items is build.

OutputWorkflow list with dependencies

4

Code check

Code examines the plan against the fixed rules. If a rule fails, the plan goes back to Adaptation one time.

Output0 faults

5

Judge and gate

A separate AI answers yes/no questions for each workflow. Code calculates the score. The pass line is 0.80. Adaptation revises a failed workflow up to 3 times.

OutputWorkflows that are ready

6

Decisions

Adaptation writes each decide workflow as a decision: options, the choice, the reason, failure cases, rules for builders.

Outputdecisions.md

7

Build

Only build workflows that are ready get credits. Each builder gets its decisions.

OutputThe site

Rules that code checks

RuleRequirement
R1Each done-when item has a build workflow. Each brief factor has a stage.
R2Only one workflow delivers each item.
R3No two stages have the same type of thinking.
R4Each stage owns a factor or touches an item.
R6Each stage has a goal, a method and a done-test.

Interface with Certainty

Realization

Sets what the work must cover.

→
Judge

Asks questions from both axes. Code sets one score.

←
Certainty

Sets how the work must be done: operate, analyze, experiment or stabilize.

When a workflow fails, the fix gets the label of the axis that must change, for example realization:split or certainty:reread.
