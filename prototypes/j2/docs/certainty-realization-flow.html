J2 · Adaptation · Memo to founder · 25 Oct 2026

J2 now checks its plan before it builds. In the first test, the result was correct and cost 25% less.

Two axes control the plan. Realization sets what the work must cover. Certainty sets how the work must be done. A separate judge then decides if each part of the plan is ready. J2 spends credits only on ready parts.

Situation

J2 gets a short brief. Adaptation cuts the brief into workflows. Builders build them. Audit checks the result.

Complication

Base J2 builds first and finds gaps at Audit. A brief does not name all of its needs. Each gap found late costs a fix round.

Resolution

Adaptation now plans in four steps: what to cover, how sure it is, a score for each workflow, decisions before the build.

How the logic works now

This is the first plan of a website run, with J2_REALIZATION=1. All steps before the build are planning calls. They use no build credits.

Requester → Identity

Brief becomes a charter

Identity writes the done-when items. Each item is a thing the result must do.

Adaptation does both in one plan

1 · Realization

What must the work cover?

  • List the factors. A factor comes from the brief, general knowledge or the budget.
  • Put factors into stages. One stage has one kind of thinking (for example compliance, design, build).
  • Cut each stage into workflows. A workflow is decide or build.
2 · Certainty

How well do we know cause and effect?

Answer 5 signals: broken, reaction, facts given, known pattern, open choices. A fixed rule gives the zone.

operateBuild directly. analyzeCompare options, choose one, then build. experimentRun 1 to 3 small tests first. stabilizeRepair only. Add nothing new.
3 · Code check

Does the plan obey the rules?

Each item has one builder. Each brief factor has a stage. The zone agrees with the signals. Code finds faults and sends the plan back one time.

4 · Judge

Is each workflow ready?

A separate AI answers yes or no to 11 fixed questions per workflow, plus questions for its items and factors. Code calculates the score: 0.95 minus the weight of each "no". The judge does not give the score.

Gate

Score 0.80 or more?

Yes

The workflow is ready.

No · Adaptation can fix it

Adaptation revises it. The judge scores it again.

↻ up to 3 rounds

No · a Requester fact

Adaptation does not guess. Identity asks the Requester one question before the build.

No after 3 rounds

It is "not ready". J2 does not build it and records the reason.

5 · Decisions

Close each decide workflow in writing

For each one: the options, the choice, the reason, how it can fail, and rules for builders. Output: decisions.md.

6 · Build in J2

Only ready build workflows get credits

Each build workflow reads its decisions. Priority funds it, a Builder builds it, Audit checks the site.

Plan confidence is the score of the weakest workflow. One weak part makes the whole plan weak.

Limits and next steps

  1. One test only. Run the other test briefs before we make a decision.
  2. The gate is not enforced yet. In the test, the gate held all build work behind one not-ready workflow. Adaptation built it anyway. Code must block held work.
  3. Builders do not always obey decisions. Make decisions a contract that Audit checks.
  4. No web access. J2 takes facts from memory. A research step must check facts against sources.
