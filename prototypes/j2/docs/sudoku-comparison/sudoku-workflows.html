J2 · Adaptation · Sudoku brief · runs of 24 Oct 2026 · 1 of 3

Realization plans and judges the work before it builds. For Sudoku, both flows passed every item. Realization wrote 7 decisions first, but used 30 more AI calls and 9 more credits.

Situation

The same brief went to two J2 flows: "Build me a Sudoku game as a single web page … for casual players … You decide the details." Both flows got 200 credits.

Complication

Base J2 cuts the charter into workflows in one AI call. Nothing checks the plan before the build. Gaps show at Audit and cost fix rounds.

Resolution

Realization lists factors, makes stages, sets a certainty zone, and has a separate judge score each workflow. Decisions are written before the build starts.

First principles

Basic factSo, Adaptation must
You can build only the needs that you know about.List the factors, also those that the brief does not state.
Each type of thinking needs its own owner.Put each type in its own stage: product, design, engineering, build.
The method depends on how well cause and effect are known.Read five gates. Set the zone. Shape each workflow to its zone.
A decision costs less than a rebuild.Write decide workflows before build workflows.
A planner cannot check its own plan.Let a separate judge answer yes/no. Let code set the score. Pass line 0.80.

How realization and certainty work together here

  • Realization made the design and engineering stages. Certainty (zone analyze) made each of them a written decision first.
  • The judge split 3 workflows on the realization question "one kind of thinking". Each split made a new workflow.
  • Every build workflow got its decisions (D-n) when it started.

CAUTION

  • D6 and D7 sit in the build stage but deliver no item, so code typed them "decide". They became written decisions, not J2 builds. The item 4 helps were built inside W-7.
  • In both flows, N6 (a J2 code check on digits) caused fix rounds that a player does not need.
  • One run of each flow. The two charters are not the same.
