# Q8: Founder checkpoints across product-doc layers

## Question

Verbatim per §14.10 row Q8 (post-2026-05-09 ratification): the row records the resolved answer in place of an open prompt. The original question shape was: which product-doc layers (L0-L14 per PRODUCT-DOC-STANDARD) get explicit founder approval checkpoints — every founder-owned layer, only the WHY layer, or only at major transitions?

## Why it matters

Checkpoint placement trades founder time investment against quality risk. Too few checkpoints → drift; founder discovers misalignment late, expensive rework. Too many → founder bottleneck, slowed cycle, ceremony cost. The founder-portfolio persona (Q1) implies high judgment-density per founder hour — checkpoints earn their time.

## Default if unanswered

n/a — answer is recorded in canon row directly; no fallback default applies once ratified.

## Answer

**Every founder-owned layer** (L1 / L2 / L3 / L4 / L6 / L7 / L11 / L14) gets a founder checkpoint. **Eight explicit gates per product-doc cycle.** Highest quality posture; founder time investment accepted as worthwhile; matches the Phase A kickoff framework in §14.15.1. Claude-owned and codex-owned layers (L0/L5/L8/L9/L10/L12/L13) ratify without founder gate but ship per-layer audit rows.
