# Spec: a planned real run runs without approval, a dry run or internet rules
Status: Refined   |   Task: remove-real-run-gates   |   Date: 2026-11-26

Inputs: the founder's brief and answers of 2026-11-26 (relayed by the coordinator), impact.md (file:line evidence at 6c79a1db), docs/ai/analysis.md. Paths are under `sutra-pro/`; line numbers are of 6c79a1db. `j2.py` means `sutra_app/engine/j2.py` (generated by `scripts/vendor_j2.py`, never hand-edited).

Design intent (founder): "Remove the safety gates around real runs for now; if something goes wrong they get added back." The goal is less code and fewer restrictions, not new features.

## Problem

A real run (a built script run once on the Requester's own folder) passes four gates before it runs. Each adds code, questions and failure paths:

| gate | what the Requester sees today | evidence |
|---|---|---|
| Run / Don't run approval (D434, P31) | a card with the command and `RUN <code>`; the run pauses until the exact reply | j2.py:6306-6318, :6344-6356; E28 port_j2_ui.py:310-317 |
| package-install approval (D447, P42) | a second card, `RUN <code>` before packages are installed | j2.py:6107-6134, :6136-6182 |
| internet rules (D449, P44) | hosts must be named in the brief or answers; otherwise a host question with Allow / Don't allow; a required `offline` command | j2.py:966-1070, :6196-6259, :10047-10056; E29 port_j2_ui.py:318-323 |
| dry run on copies (D434, D435, D438, D446) | the command runs first on copies, with placeholder secret files and no network; failures go back to the build | j2.py:803-811, :1092-1135, :6261-6342 |
| answer rules (D448, P43) | an answer never confirms a done-when item the charter marks real-run | j2.py:7061-7076 |

## Goals

- A real run in an accepted plan runs once, when the rest is workable, with no question to the Requester.
- Package installs for a build run with no question.
- No dry run, no copies, no placeholder secret files, no `offline` field.
- The planner lists the hosts a script reaches; code checks only their syntax; nobody is asked.
- Fewer lines in the engine than today; no flag that brings the old behaviour back.
- A run whose required real run did not happen or did not pass never ends "Done:"; it ends "Done with open items" with the reason.

## Non-goals

- No new feature, card or button. One E edit only: E31 takes "approved by you" / "not approved" out of the Deliverables' "Run for real" list (j2_ui.html:2407, J2's own page text, which reads `approved`; no row carries it any more, FR-27).
- No change to the secret handling of D446 (clean environment, secret files by path only, never printed, base allowlist, guardrail list).
- No P45 key in the `real_run` row: this change adds no `result`, `run_output`, `created`, `changed` or `deleted` key (P45, another developer, not on any branch: `git log --all --grep P45` and a scan of every ref for `Edit("P45"` find none). Only gate keys nobody reads any more leave the row (FR-27, FR-28).
- No change to srt's write limit, the test rerun's sandbox settings (j2.py:625-629) or the PyPI install's own srt settings (runenv.py:198).
- No change to `prototypes/j2` (AGENTS.md "Stay in sutra-pro/").
- No Pulse-specific logic, no hard-coded hosts, folders or project names.

## Functional requirements

### R1 The real run runs without approval (removes D434's approval; J2 step 7)
- **FR-1** At the two points that ask for a real run today (j2.py:7331, :7595), code runs the next done workflow's real run directly: no card, no one-time code, no pause.
- **FR-2** Each workflow id's real run runs at most once, counted by the `real_run` rows in the run folder's receipts.jsonl (so a follow-up, which copies that file, never runs a parent's real run again; C-19). A real run that failed is never run again by itself (D449 part 6 stays). A replacement workflow (a new id) runs its own real run once, unasked (Q-1). A workflow saved while its Run card or host question waited has no `real_run` row, so a follow-up that reaches step 7 runs it (Q-6).
- **FR-3** No pause of kind `real_run` or `hosts` is ever created. `PAUSES`, `AUTO_ASK` and `DECISION_PAUSES` no longer name them; `REAL_RUN_DECLINE`, `HOSTS_DECLINE`, `HOSTS_DENY` and `real_runs_asked` are gone; the snapshot's `paused` has no `code` key.
- **FR-4** The page has no Run, Don't run, Allow or Don't allow button: E28a, E28b and E29 are deleted from `scripts/port_j2_ui.py` and from the mirror in `tests/ui/test_port_edits.py`; E31 deletes `` ` · ${r.approved ? "approved by you" : "not approved"}` `` from the Deliverables' "Run for real" line; `j2_ui.html` is re-ported. The edit count in port_j2_ui.py:18 is updated.
- **FR-5** After the run, code does what it does today after an approved run: posts "Ran for real: <evidence>." (or the evidence of a run that did not start), runs the P33 Audit call when the run exited 0 (subject to FR-14), sets the items' verdicts from the receipt and Audit, then `_goal_done` (C-6).
- **FR-6** The receipt answer Identity and Audit get (`_real_run_answer`) says whether the real run ran and its evidence. It never says "approved", "not approved" or that code asks the Requester. `j2_artifacts._deliverable_extras` no longer projects `approved` (j2_artifacts.py:775).

### R2 Package installs run without approval (removes D447's approval; keeps its environment)
- **FR-7** A build whose `requirements.txt` has no installed environment gets it installed at the point where code asks today, with no question: PyPI only, the same srt settings and clean environment as today (runenv.py:198; `llm.run_env()`). One info line names the packages and where they go; an `env_install` row is written; the build's checks go on.
- **FR-8** A failed install goes back to the builder with pip's error, as today (j2.py:6175-6180), and the same requirements hash is not installed again in the run (`env_why`).
- **FR-9** Before a real run starts, a missing package or an import that does not resolve still sends the workflow back to the builder without running it (today's `_env_stops_real_run`). Its failure kind, message and Adaptation reason do not mention a dry run or copies (Q-3).

### R3 No dry run, no `offline`, no placeholders (removes D435, the dry-run parts of D434, D438, D446 and D449)
- **FR-10** Nothing copies the named folders, rewrites the command's paths, writes placeholder secret files or runs the command more than once. `real_run_dry`, `dry_secret_files`, `real_run`'s `fence` branch, the placeholder `deny_read` entries and `real_runs_dry` are gone.
- **FR-11** A planned real run has no `offline` field. The planner's rule does not ask for it, `_register` does not require or check it, and nothing stores it. A plan that still sends `offline` registers; the field is not stored.
- **FR-12** A plan whose command does not pass its folder and read folders as arguments is not refused for that (the j2.py:731-737 rule is gone).
- **FR-13** A build that writes a real folder path into one of its files is not refused or rebuilt for that (`_real_path_leak` and its two callers are gone; `real_paths_in` goes with them if nothing else uses it).

### R4 The expect check after the run (keeps D438's `expect`)
- **FR-14** `_register` still refuses a real run without a valid `expect` (P35's `real_run_expect_problems`, key `real_run_expect`).
- **FR-15** When the real run starts, code records every file under its `folder` (relative path and sha256) before and after the command, and computes created, changed and deleted from the two records. `reads` folders are not recorded.
- **FR-16** When the run exited 0 and that diff differs from `expect` (P35's `expect_mismatch` rule), every done-when item the run checks gets NEEDS_REVISION with the note "not what it said it would do: <mismatch>". The real run is not repeated. The P33 Audit call is not made for that run (Q-4).
- **FR-17** The diff is not written into the receipt row as `created`, `changed` or `deleted` keys. On a mismatch, the row's existing optional `audit` key carries `{<item>: {"verdict": "NEEDS_REVISION", "evidence": "<mismatch>"}}` for each item the run checks (Q-5).
- **FR-18** The P33 Audit prompt gives the real run's own diff (FR-15) in place of "WHAT THE DRY RUN DID TO THE COPY".

### R5 Hosts: listed freely, syntax-checked only (removes D449's naming rules and question)
- **FR-19** `hosts` stays optional. Each entry must pass today's syntax check (`host_entry_ok`); a bad entry is refused with key `real_run_hosts`, as today. No other rule applies to hosts: none about the brief, the answers, a pick or the charter.
- **FR-20** No host question exists: `hosts_ask`, `hosts_asked`, `_hosts_to_ask`, `_ask_hosts`, `_hosts_answered`, `host_pieces`, `host_named` and the `reaches` field are gone.
- **FR-21** The real run's srt settings allow exactly the plan's hosts (`real_hosts`, lower case, each once), and `[]` with none. The filesystem settings are today's minus the placeholder entries (FR-10): `denyRead: ["~"]`, `allowRead` of the built folder, the folder, the reads, the environment's reads and the real secret-file paths, `allowWrite: [folder]`, today's `denyWrite`.
- **FR-22** The planner's internet rule and the tools builder's line ask to list every host the script reaches (bare name, optional `*.` and `:port`) and never to set the four proxy settings. They say nothing about `offline`, naming by the brief, asking the Requester, a Run card or approval.
- **FR-23** Settings named `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` or `NO_PROXY` are still refused, with or without hosts (D446 guardrail list, llm.py:165-174).

### R6 Answers (removes D448's real-run confirmation part only)
- **FR-24** An answer can confirm a done-when item the charter marks real-run, exactly as it confirms any other item. The P43 lines at j2.py:7061-7076 are gone, including the "Noted. This part is checked ..." line and the sentence appended to J2's own note.
- **FR-25** A folder or secret file must still be named whole in the brief, the Requester's typed answers or the Requester's own bare pick (`picked`); Decide for me's picks and the charter never count (C-14 unchanged).

### R7 What stays

- **FR-27** A `real_run` row is exactly: `type`, `workflow`, the stored plan (`command`, `folder`, `reads`, `why`, `expect`, `checks`, then `settings`, `secret_files`, `hosts` each only when stated), the result of `real_run` (`ran`, `exit`, then `output`, `stdout`, `stderr`, `env`, `seconds`, `sha256`, `evidence` as today), `audit` (only when Audit judged or `expect` did not match), `t`, `by`. `code`, `approved`, `answer_msg`, `dry_run` and `offline` are not written: after FR-4 and FR-6 nothing reads them (C-8; the tests that read `approved` test the removed approval and are rewritten). ### R7b A run never ends "Done:" without its required real run (new, founder 2026-11-26)
