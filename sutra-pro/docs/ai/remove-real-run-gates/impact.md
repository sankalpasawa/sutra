## 3. srt today, and what "open its network" means
- Settings per run, written to a temp file next to the output folder (j2.py:932-942):
  `{"network": {"allowedDomains": [] if fence else hosts, "deniedDomains": []}, "filesystem": {"denyRead": ["~"] + deny_read, "allowRead": [out_dir, folder] + reads + env reads + secret paths, "allowWrite": [folder], "denyWrite": ["/tmp/claude", "/private/tmp/claude"]}}`. srt is started as `srt -s <conf> -c "<env NAME=v ...> <command>"` (j2.py:944-951).
- srt is used for the real run only when `sandbox_on()` (j2.py:913, llm.py:142-147). Without srt the real run is a plain process: full network, no write limit.
- The test rerun (`sandbox_settings` j2.py:625-629) and the PyPI install (runenv.py:198, PyPI hosts only) have their own settings. They are out of scope.
- **srt cannot be opened to every host by settings.** srt 0.0.81 is allow-only ("By default, all network access is denied ... An empty allowedDomains list means no network access", srt README:122, :456-458). It refuses `"*"`, `"*.*"` and `"*:443"` with "Overly broad patterns like "*.com" or "*" are not allowed for security reasons" (tried in the scratchpad, `srt -s <conf> -c 'echo ran'`, 2026-11-26). The ask callback and per-command lists are library APIs only (README:321, :345), not the CLI. So "keep srt for writes but open its network" is not a one-line change. The options for the architect:
  | Option | Writes limited | Network | Effort |
  |---|---|---|---|
  | a. Run the real run without srt (plain process, as with the sandbox off) | no (loses K4) | all | smallest |
  | b. Keep srt, pass the plan's hosts as today but with no rule on where they come from (the planner lists them; no question) | yes | only the listed hosts | small (delete the naming rules and the question, keep `real_hosts` and `host_entry_ok`) |
  | c. A wrapper around srt's library (`SandboxManager`) with an ask callback that allows every host | yes | all | a new Node file and a dependency on srt's API (unverified that it allows an "allow all" answer) |
  | d. Use sandbox-exec (macOS) or bwrap (Linux) directly for the filesystem only | yes | all | new code per platform |
  Confidence: high that srt's CLI has no allow-all setting (README plus the refusal). Moderate that option b is the only small change that keeps K4.

## 7. Risks (ranked)
1. **The srt network cannot be opened by config** (section 3). "Keep srt for writes, open network" needs option b (still a host list), c or d. Without srt the real run writes anywhere.
2. **The receipt row shape** (K2). Without the approval and the dry run, `code`, `approved`, `answer_msg` and `dry_run` lose their meaning, and `hosts`/`offline` disappear from the `**rr` spread. Readers: j2_artifacts.py:775 and `_real_run_answer`. Kaivan's P45 also adds created/changed/deleted, the same diff the expect check now needs. Agree with him who writes those keys.
3. **The expect check loses its "send it back before harm" meaning.** After the run the files are already changed. A mismatch can only fail the item or alert. It can never be retried by itself (D449 part 6).
4. **P42 is tangled in R1 and R3**: pause kind `real_run`, `REAL_RUN_DECLINE`, `real_runs_asked`, E28 and `_dry_run_failed`. Removing R1 carelessly breaks package installs (test_p42_*).
5. **Patches amend each other**: P31, P35 and P41 edits were rewritten by P43 and P44 edits (vendor_j2.py:2832-2833 re-anchors P35's line, for example). Deleting a later patch's edit may leave an earlier edit's anchor missing, and `vendor_j2.py --check` fails on any count mismatch. Re-run the extraction check after each patch is changed.
6. **Prompt text in data files** (identity.md:43, real_run.md:1) still promises the approval and copies. vendor_j2.py has no data-file edit. Leaving them makes the model tell the Requester about a Run step that no longer exists. Changing them needs a new mechanism or a code-side replacement (prompt-changing, D249).
7. **Picked options** (R4): removing `picked` makes a clicked folder or secret file "not named" again, so the run is refused and asked again, unless the naming rule itself goes (Q2).
8. **Decide for me**: with `real_run` out of the approval, nothing stops Decide for me from reaching a real run. That is the intended outcome, and it is new behaviour for the owner to accept. With the sandbox off (Windows, no srt) a real run is unfenced and unasked.
