### What is new in 0.8.0

- **Named projects.** "+ New project" opens a Create project box: you type the project's name (required) and may pick its folder; with no folder it gets `Documents/Sutra Pro/<name>`. After you pick a folder, Sutra asks whether its team may read and edit there, or only read.
- **You choose where each prompt goes.** The start heading reads "What should we make in <Project>?" and the name is a dropdown of your projects. On Attention it starts on the last project you used, and also offers "Let Sutra choose".
- **The org chat asks before it starts a project.** With "Let Sutra choose", a request no project fits gets a card with a suggested name; "Name it…" opens the Create project box. No project is made until you say yes.
- **Rename and Delete** are in each project's ⋯ menu. Delete asks first, is refused while the project works, hides the project, and keeps its runs and files on disk.
- **Results land in the project's folder.** A finished run copies what it made (documents, project work, an app's files) into the project's own folder. A file you changed there by hand is never overwritten, and the chat says so. `<folder>/.sutra/manifest.json` records what Sutra wrote.
- **A follow-up continues the work.** The next prompt in a project continues the last finished run, including project work and app builds. It starts from the files in the folder, including your own edits, and writes back only the files it changed.
- **A working folder no longer turns a request into single-team project work.** The planner plans stages and charters as usual. The "Project work" choice still selects it.
- **Your data is upgraded once** to schema 9 (one new column). An older app cannot open a database that 0.8.0 has upgraded: keep the `pre-upgrade` copy, or run `sutra-pro backup --to <folder>` first, if you may want to go back.
- **Not tried yet in the desktop app:** the Create project box, the project dropdown and the ⋯ menu were checked through the server and the tests, not clicked by hand.
