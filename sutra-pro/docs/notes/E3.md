# E3 as built: the host process
## Built (engine.md 4.5 to 4.7, flows F1 F4 F5 F7; `sutra_app/engine/`, tests in `tests/engine/`)
- `__main__.py` calls `host.loop.main()`. `host/loop.py`: `main(argv, *, make_port=None)` and `Host`: folder and `task.json`
  checks, settings layering + env export before `engine.j2` is imported, library seed, port + preflight, hooks, `J2Run`, seed
  decision, `run.started`, host `system` lines, the 150 ms tick, stop, SIGTERM, dead-thread watch, `run.ended`.
- `host/inbox.py`: `InboxTailer` (whole lines only, `n` order, bad lines skipped with `inbox.skipped`), `Inbox` (FIFO, delivery
  rule, one `inbox.deferred` per head, `stop` clears the queue and the rest of its batch with `inbox.discarded`, `close()`).
- `host/publisher.py`: `StatePublisher` (snapshot.json / live.json atomically and on change; node, step, atom/1 events from
  `j2_map.build` + the snapshot, `wait_on` mapped back through `NAMES`, `tokens` from the map function node) and `HostHooks`
  (wraps the hooks: remembers the `run_error` code, publishes at every turn boundary). `host/heartbeat.py`: the daemon thread.
- Tests (111, about 17 s): host 46, publisher 39, crash 19, process 6, live 2 (skipped without SUTRA_LIVE=1).
## Deviations from the specification
1. `run.started` is emitted after the seed decision and before the host's own `system` lines, so those lines (and a continued run's
   "Continuing from run ..." line) come after it; the heartbeat starts right after `run.started`, before the first publish.
2. `J2Run` has no `stopping` flag in the vendored `j2.py` (E1 owns it), so the crash path of a stopped run still tries the reviewer
   call; with the port closed it fails at once, and the host rewrites the outcome, `summary.json` (status stopped) and clears
   `error`. The host sets `run.stopping = True` for a later E1 patch to read. The stop took 0.5 s in tests (limit 6 s).
3. Hook factory call: `factory(writer=, notify=, validator=, node_context_file=, spec=TaskSpec)`; `node_context_file` is
   `<run>/node_context.json` (not named in the design).
4. A team step has the id `team:<persona>` (one per persona, status = the worst of its boxes, parent null); a builder step's parent
   is its box id (`work:website`). A function node's `task` and `context` come from the `TurnInfo` seen by `HostHooks`.
5. Extra trace types: `task.settings_dropped`, `inbox.stop`, `inbox.discarded`, `seed.refused`, `seed.skipped`, `upstream.skipped`,
   `thread.died`. A refused upstream file is skipped, never an error. A refused seed copies the old site, `*.md`, `*.docx`,
   `goal/summary/workflows/documents.json` to `upstream/<old id>/` (not logs, not events).
6. `seed_from` that is not a run folder of this department: seed `fresh`, no system line.
7. Exit 3 also for bad settings layers and an unusable records hook; exit 2 for a bad folder or task.
8. SIGTERM: the handler closes the port and sets a flag; the main loop (150 ms) writes `run.ended{stopped}` and returns 143.
9. A uncaught thread exception (the hook also hears SystemExit) or a run that is `running` with a free lock for 1 s ends the run
   as crashed, code `internal` (code from `run_error` when J2 reported one).
## Decisions
- In-process tests import J2 anew per test (`fresh_j2`, from E1's patch tests): J2 reads its environment at import. Process tests
  fake Chrome through a `SUTRA_HOOKS` factory defined in the test module.
- The publisher builds the map from `live` only while the run is running or paused (as `views`); otherwise from the folder.
- A user line is delivered when `run.status == "waiting"` (also when finished but not ended); a finished run is over only when
  its lock is free and the FIFO empty after one more drain.
## Known limits
- `fnodes.layer` is not merged (E6): the default hooks target falls back to `EventHooks` with one `publish.error` line. The
  connector `engine_port.make_port` is not merged (CN): a real-model run says "could not start: the model connectors are not
  available" (tested with a fake module); `test_engine_live.py` is written against the specified signature, never run here.
- POSIX only. Reading `J2Run` from the publisher thread is the design's benign race (one retry). Node events carry the lane
  text as `detail` (about 150 per Brew Lab run).
