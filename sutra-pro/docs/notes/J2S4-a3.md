## The agent_answer scenario (the one prompt J2's agent view adds)
The `realization` run (J2's default flags), then `j2_agent.answer(run_dir, "adaptation", "Why was W-3 scored below the gate?", ask=stub)`.
The stub stands in for the model and returns a fixed text; the child fails unless the model is asked exactly once, with `max_tokens=700`,
`effort="low"` and the records fallback as the third argument (the contract lane C's port implements), and unless the answer comes back
as `{who, answer, from: "model"}`. The golden's last call is `["adaptation", sha(system), sha(user)]`; the 24 calls before it equal
`prompts_realization.json`. The user text lists the run's records, so two things in it are not the same from run to run:
- J2 stamps chat lines and AI calls with the time of day (`time.strftime("%H:%M:%S")`, no date) and sorts a function's feed by it: a run
  that crosses a second boundary lists the same records in another order. The child fixes that one format at `12:00:00`
  (`freeze_time_of_day`, for J2's and for the engine's run alike; ISO stamps and run ids stay real). Measured with 48 runs
  at once (24 J2, 24 engine; the batch took 3.4 s, so runs crossed second boundaries): one distinct prompt with the fix, five without it.
- The AI-call lines carry wall-clock seconds (` · 0.0 s`, ` · 0 s`): `feed_digest` replaces each `N s` by `<s>` before hashing.
