# L5 as built: Workflow, Step and the five function models

Built (library design sections 6 and 9.1, DL8): `workflow.py` (Resources, Envelope, Step / AIStep / CodeStep / AssignmentStep,
Workflow, TaskWorkflow, DeptWorkflow, ProposedWorkflow, RegisteredWorkflow, Research, Experiment, `to_j2`, `from_j2`,
`registered_from_j2`) and `functions.py` (14 reply classes in the 5 function families, Certainty with `certainty_zone`, Conflict,
Lesson, the realization parts). Two test files, 167 cases, under 1 s. Checked against J2 33aeeda data: EXAMPLE_WORKFLOW round-trips
(`to_j2(from_j2(x)) == x + id`), one real workflows.json row round-trips, all 27 current-vintage saved conflicts validate (14 older
ones, with no `topic`, do not), `certainty_zone` agrees with a plain reference on all 243 signal combinations.

## Deviations from the specification
- Department steps are typed `AIStep | CodeStep` only (the spec's base takes all three step kinds). A wrong kind is `union_tag_invalid`
  instead of `value_error`, and the model's transport schema no longer offers an `assignment` step. `Workflow` itself keeps all three.
- `RegisteredWorkflow` is a `DeptWorkflow`: J2's `atoms` (atom dicts) are its `steps`, its `atoms` field is the id list `W-n.a1` and must
  equal `<id>.<step id>`. `registered_from_j2(row)` converts a workflows.json row (`purpose` fills `goal_gap`); a legacy row with no atoms fails.
- `Envelope` reads `null` as the default for `time_limit_minutes` and `stop_loss` (2 of 500 saved envelopes). `Conflict` takes the keys
  J2's code sets (final positions, repricing, document rounds), status `repricing`, resolved_by `default`, `attempts.agree` null.
- `Lesson` is a Record of its own family `lesson` (the design lists none); J2's lines have no `kind`, so L8 adds it, as for goal.
- Stage ids are a pattern, not the 35 ids of `stages.json` (the library reads no engine file); `plan_faults` checks membership.
- `from_j2(d, *, id="P-1")`: EXAMPLE_WORKFLOW has no id, so the id is the dict's, else the keyword. `to_j2` always writes `id`.
- `ruling` is a free string (spec `S?`); `FindingRow` severity and confidence may be null (stored Finding allows it).

## Decisions
- Transport: `schema_version` and `reason` are optional on every reply; every optional class or union field (intake `goal`, ruling and
  approval_ask `user_question`, propose `dispute`, `certainty_assessment`, `analysis`, `deferred`, the five realization lists) is in
  `TRANSPORT_OPTIONAL` and the model omits it (L1 review). A test walks all 14 schemas: no single-member `anyOf` is required.
  ProposedWorkflow also leaves its plan fields, envelope and code-set fields optional; it asks what J2's WF_FMT asks.
- `next` is required where the design lists it. `PASS_WITH_WARNING` needs evidence as `PASS` does (L3's Finding agrees).
- A step's name is the first 120 characters of its goal (J2's atoms have no name); the J2 `target` list of one item becomes a string.

## Known limits
- Transport schemas carry the whole `AtomDraft` per step (propose 15.9 KB, price 10.7 KB, respond 10.6 KB), including `Check.results`
  and `target_sha256` the model should never fill. A slimmer model-facing check would need a change in atom.py (L4).
- `to_j2` drops what J2's six atom fields cannot hold (touches, outputs, depends_on, supersedes, model, effort); `from_j2` drops keys
  the model lacks (an explicit `count: 1`, check `item` numbers, `cost` and `estimate` of a priced proposal).
- Conflict's final positions are opaque JSON; a key J2 adds later fails L8's golden run, which is how the list stays complete.

## Follow-ups for other packages
- L8: `Lesson` and `Conflict` rows need `kind` added before `GATE.check`; register `workflow:registered` rows through `registered_from_j2`.
- L10: the reply families and kinds named by `TaskKind` exist as in the table of section 6; `verify_refs` can now run on them.
- Orchestrator: `AssignmentPlan.to_task_workflow` builds `TaskWorkflow(id="req-<n>", steps=[AssignmentStep...])` (kind defaults are set).

## Mutation check
27 hand-made mutants (comparisons, constants, dropped validations and error branches, widened types, inverted conditions,
transport-optional sets) in one pass: 24 killed first time. The 3 left: `first[dep] >= index` could never be true (removed from the
code), a grep-count minimum of 0 (test added), the lower-casing of `split` (test added). No second round.
