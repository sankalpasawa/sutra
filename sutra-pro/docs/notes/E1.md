# E1 as built: the vendored J2 engine, patches P1-P11, rehydrate

## Built (engine.md 3.1, 3.4, 4.8, 8; `sutra_app/engine/`, `scripts/vendor_j2.py`, `docs/reference/j2/`)
- The 14 J2 code modules, the 10 role files, 4 conditions, `artifacts/types.json`, 5 generic templates and the 105-file seed library
  (26 templates) are copied from J2 `33aeeda` (PR #30, not `ce2631f`) by `scripts/vendor_j2.py`: exact-text edits that name how often
  each anchor must occur, so a J2 change under an anchor stops the run. `--source <J2 checkout> --check` (or `SUTRA_J2_CHECKOUT`)
  re-derives the whole tree in memory and exits 1 on any difference; it passes. `VENDORED.md` (generated) holds the commit, the sha256 of
  every J2 file and its copy, and the patch table with the line ranges. Located by anchor text, never by line (j2-sync.md).
- Patches P1-P5, P7-P11 (there is no P6: the design's table skips it). P1 relative imports (incl. the 3 lazy ones), P2 `J2_AGENTS_DIR`,
  P3 `J2Run(run_dir=, run_id=, hooks=)`, P4 non-blocking `user_says` + `apply_override`, P5 explicit-path variants, P7 `llm.tagged` around
  every model call, P8 hook calls, P9 `system_addendum`, P10 library `flock` + `LibraryBusy`, P11 `J2Run.rehydrate` -> `rehydrate.py`.
- `rehydrate.py`: `check_source` (reads, writes nothing), `rehydrate(run, src_dir)`, `RehydrateRefused`, `continuing_line`, `fresh_line`.
  Conditions: summary done / done_with_open_items, `chat.jsonl` header output website, no document chain, `goal.json` + `workflows.json`
  readable. Realization on or off is not a condition; `real`, `real_base`, `real_summary`, `real_asked` come back when `realization.json` exists.
- Tests (105 in five files, about 12 s): vendor 15, patches 49, features 5 (+ parametrised per feature), library lock 10, rehydrate 26.

## Decisions and deviations
1. P8 gets a small helper `J2Run._run_status()` (posts `run_status` only for an observed run) so the three end-of-turn sites stay one line.
2. `rehydrate` restores `calls` from `summary.json` `ai_calls` (never below the highest id in `calls.jsonl`). The reviewer call is counted after
   `summary.json` is written and J2 does not log it, so a continued run starts one call short of the old process: the next logged id is
   still unique. Chosen over guessing; tested.
3. A site, `artifacts/` file or JSON that is a symlink is neither read nor copied; a copy that fails half way is undone (refusal, not error).
4. Board re-checks in `audits.json` (kind `recheck`) are not audits and are dropped; the message board, template-library state and
   J2_CHANGE state are not restored (off by default, not needed for a change request). Documented in the module docstring.
5. `test_engine_library_lock.py` cuts `LOCK_WAIT_S` to 0.2-0.3 s for the busy tests (the constant is asserted to be 30.0) and runs a real
   Brew Lab run with `J2_TEMPLATE_LIBRARY=1` and `J2_BUDGET=1400` (J2's own value for library runs; the default 100 pauses on a conflict).
6. The document-chain `xfail` (strict) is in place; E1-b (lifting the limit) and E1-c (one runtime copy with the library) are NOT done here.
7. The vendor test that re-runs `vendor_j2.py --check` skips without `SUTRA_J2_CHECKOUT` (the J2 repo is read-only and absent in CI).

## Known limits
- `rehydrate` is proven in mock mode only (as the risk table says); a real-model follow-up with realization on is unverified.
- `fcntl` is POSIX only. The vendored `j2_check.py` has a `\d` in a normal string (a DeprecationWarning from J2's own code, left byte-identical).
- Mutation self-check: one pass, 16 breakages (P4 x2, P5, P7, P8, P9, P10 x3, rehydrate x6, a removed role file), all killed, no survivors.

## Follow-ups for other packages
- E2/E3: call `J2Run.rehydrate` before posting any host line (framing, upstream list); use `rehydrate.continuing_line/fresh_line` for the two fixed system lines.
- E3 sets `J2_RUNS_DIR`, `J2_MEMORY_FILE`, `J2_PLAYBOOK_FILE`, `J2_LIBRARY_DIR` and seeds `data/library` from `engine/seed/library`.
- E5: prompt goldens must be recorded against this vendored `j2.py`; any later J2 re-sync is `vendor_j2.py --source ... --commit ...`.
- E1-b / E1-c are the open work items of the design (document chains; one copy of models and rules after L7, L8, E5).
