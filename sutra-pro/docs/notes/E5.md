# E5 as built: legacy J2 suites as subprocesses, prompt goldens

## Built (engine.md 9, ENG-01 and ENG-10; J2 sync 2026-11-04, baseline 33aeeda)
- `tests/engine/legacy/`: `j2_flow_test.py`, `change_test.py`, `realization_test.py`, `j2_replay_size.py` from J2 `33aeeda`
  (the flow script is the one with the per-run template checks), `EXPECTED.json` (minimums: 67 lines ending " ok" for the flow
  script, 192 and 97 checks), run by `test_engine_legacy.py` in subprocesses with a clean environment and a temp cwd.
- `scripts/record_engine_golden.py` + `golden/prompts_*.json`: six mock scenarios (Brew Lab fixes 0, fixes 1, realization on,
  PRD, design-docs chain, template library on) recorded from J2 `33aeeda` via git archive: outcome, spend, page/sections/
  workflows hashes and per call `[function, sha(system), sha(prompt)]`. All six are deterministic (`--check` twice) and the
  vendored engine equals them exactly (28, 29, 24, 17, 73 and 24 calls). `test_engine_prompts.py` runs the engine side.
- `scripts/engine_gate.sh`: flow `--fast`, change and realization in three throw-away copies at once (`--fast --browser` as a
  fourth with `SUTRA_BROWSER=1` and node); checks exit, last line, no Traceback, the recorded minimums. About 75 s.
- Tests: 38 (+2 skipped without a J2 checkout, +1 browser). About 12 s without the slow flow script, 90 s with it.

## Edits to the ported scripts (beyond the design's list)
1. Imports: `from sutra_app.engine import j2 ...`; the two small scripts keep `import j2_flow_test as F` (sibling).
2. `HERE` = `SUTRA_J2_CHECKOUT` or the legacy folder; `page_file(name)` raises `NeedsPage` when J2's page/harness file is
   missing. Instead of editing 47 blocks, `skippable` wraps the blocks that can reach them (list before `__main__`): on `NeedsPage`
   it prints "skipped the rest of X: why", restores environment, `j2`/`j2_server`/`j2_check` attributes and fixed-name runs.
   Consequence: the part of such a block AFTER its first page access does not run without a checkout.
3. `served_page` (page markup checks skip on the adapter's 404), `write_png` (generated screenshot), saved-run blocks raise
   `NeedsPage` when no run exists, `template_library` reads the page only if present, reads `j2_template_lib`/`j2_server`
   source from the engine modules.
4. Skipped on purpose: `plain_unchanged` (prints the reason; prompt goldens replace it), the `git show main:j2_map.py`
   comparison, the `llm._run_claude_cli` reply cases (the CLI lives in the Claude connector, tests C15), the real `claude` CLI
   schema validation unless `SUTRA_LIVE=1` (it called the real CLI when installed). `REAL_MEMORY` fingerprint dropped.
5. Demo flags (`--board-demo` etc.) refuse to run without a checkout (they save runs into it).

## Decisions
- Prompt goldens are NOT marked slow (six runs side by side, about 3 s): they guard every merge, not only SUTRA_SLOW ones.
- Goldens hold 12-hex digests, not texts; a failure names the first differing call and whether system or prompt differs.
- The flow script is 75 s here, not 3-6 min: J2's saved runs are absent, so those blocks skip.
- Mutation check (one pass): 15 breakages of recorder, ported helpers, gate script and one engine prompt, all killed.

## Known limits / follow-ups
- Blocks that need J2's page, node harness or saved runs run only with `SUTRA_J2_CHECKOUT` (not tried in CI; the UI package
  owns the page). `--browser` is unverified here (no Chrome run).
- After a J2 re-sync: `record_engine_golden.py --source J2 --commit X`, update `EXPECTED.json`, re-copy the four scripts and re-apply
  the edits above (`diff` against the J2 file shows only them).
- E1-c (shims over the library's models) must keep `test_engine_prompts.py` and the flow script green.
