## D166 (page part) — The page builds its choices from the engine's answer
- Sources: D129, D166 (backend part, lane E), `output_pick.js`, `settings_view.js`.
- Decided: `output_pick.js` and `settings_view.js` carry no type name. The start page's "What should we make?" select is "Let the team decide" (`auto`) first, then every row of `output_types` of `GET /api/engine/settings` whose `pin` is true, in the data's order and with the data's `label`; a value in force that is not listed is added after them (shown, not lost). The Engine settings page builds the `output` choice the same way (`choicesOf`, `choiceLabel`); a settings answer that does not list its types (an older one) leaves only `auto` and what is in force, and the page then checks only the shape of a name (`[a-z][a-z0-9_]{1,40}`). `OutputPick.OPTIONS` and its table of three extra labels are removed; `typesOf(settings)` is new. The fake backend answers like the real route: `output_types` in the settings view, `output` validated by shape and by membership, `POST /api/output` refusing a name the data lacks.
- Why: a closed list in the page is a list of types in app code, and it would hide a type the user's planner just made.
- Rejected: keeping the four-option list and adding the new types to it (the next sync breaks the same way); reading `types.json` from the page (the page must not know where the data is; the engine's answer is the contract).
- Diagram: label "output choices from the data", pill on band:EXPERIENCE (shared with E).

## D167 (rehydrate and function nodes) — Old runs open by form and by shape, never by name
- Sources: handoff change 2, J2's `saved_output`, `is_page`, `LEGACY_OUTPUT`, `recorded`; lane E decides the live state and the run rows.
- Decided: `rehydrate.py` has no list of types. A stage is a document when `j2_types.info(kind)["form"] == "document"` (a type the run itself recorded and the data no longer lists counts too: J2's `recorded`), a page when `j2.is_page(kind)`, and a stage that is neither is a send deed. A single-stage run (no `documents.json`, no `stage-*.json`) is continued when `j2.saved_output(run folder)` is a page, otherwise refused with "the earlier run has no page and no document chain"; that covers a document run that left no chain and a run that stopped before a type was chosen (`output: null` in its header). The page stage's blueprint is the first of the page type's `depends_on` whose chain record has sections of the blueprint's shape (a non-empty list of objects with `id`, `anchor` and `implements`), set with the same `WF_FMT`/`GRANT_FMT` text as `J2Run._begin_stage`; J2 itself names its `lld` there, the state test compares the two for the shipped chain. A classic follow-up whose new run has no type chosen takes the earlier run's type (`RESTORED_TYPE`: `output`, `out`, `doc`); a type the host already pinned is left alone. `fnodes/registry.py`: `workable_problems` follows `j2.is_page(audit.get("output", j2.LEGACY_OUTPUT))` (J2 is imported when a verdict is asked for), and `stamp_check(goal, output)` names what is built by the type's label as J2 now does ("the output" when no type is chosen); the check passes `turn.stage`.
- Why: a name list in `rehydrate.py` refuses a new document type's chain (the owner's custom types would be dead ends); J2 no longer has a default, so a run with no type must open and must not be mistaken for a website.
- Rejected: treating a run with no type as a website (J2 does not, and the run list would lie); refusing every chain that ends in a type outside the first three; a blueprint named `lld` (a name in code).
- Diagram: label "runs without a type open", pill on band:EXPERIENCE (shared with E).

## D169 (page part) — The Engine settings page shows the builder time limit
- Sources: D169 (backend, lane E), `settings_view.js`.
- Decided: the row "Builder time limit (seconds)" with the hint "A builder's AI call that runs longer is stopped and tried once more; 0 means no limit"; it is a decimal field (`FLOATS`), so `0`, `90.5` and `600` are read as numbers. The UI fixture `engine-settings.json` and the fake backend list `builder_timeout` (default 600.0, editable).

- Rejected: leaving it to the environment only.

## D171 — The library's mirrors of J2's former section models are retired; template artifact names are data
- Sources: D46 (the drift test), `docs/design/library.md`, J2's `templates/<type>/generic.json`.
- Decided: `sutra_app/library/artifacts/` (the 19 section models and 3 document models, the rules as data, the renderers), the generic layer of `templates.py` (`generic`, `generic_file`, `write_generic`, `generic_drift`, `from_model`, `templates_dir`, `ARTIFACTS`) and the generated `docs/schemas/artifact.*` (22 files) and `docs/schemas/templates/` (5 files) are removed. What stays is the field-driven machinery: `templates.py` (the Template classes, the checks, `build_model`, `validate`, run templates) and `rules.py` (`RuleSpec`, the 12 rule functions, `run_specs`; no per-type data; a `ref_exists` target is `this.` or an artifact name by shape). `TemplateArtifact` is an `ArtifactName` (`[a-z][a-z0-9_]{1,40}`, in `types.py`). Three consequences, each on purpose: (1) `SpecialisedTemplate` checks that `extends` is the generic's reference but no longer that it keeps the generic's required fields (`keeps_problems(generic, template)` is still there for whoever holds the generic: J2); (2) a template's transport marks a field optional when the template says it is not required or when the caller passes `reply_optional` (and `generic`, to tell the generic's own fields from added ones): J2's `reply_optional` of the generic.json, which the library no longer holds; (3) `validate` checks the template's runtime class and normalises enum casing from the template's own enums (`ENUMS`), but J2's `requires_one_of` (a website section's "html or head") is J2's check on its own file. The parity test keeps the rule layer (run on J2's own rule data) and the Certainty-zone and JSON-extract parts; `parity_allowlist.json` (the one model disagreement) is removed with the model parity. `tests/library/test_lib_rules.py` reads the rules from the frozen generic files (`fixtures/artifacts/generic/`) and compares with J2's recorded answers (100 cases).
- Why: J2 no longer has the models the mirrors were bound to; the vendored generic templates are the single source; the mirrors named three types in code.
- Rejected: keeping the mirrors as a frozen copy (it drifts silently and keeps the type names); re-pointing them at the generic templates (a second reader of files J2 already reads); a hook in the library to fetch the generic (the library imports nothing from the engine).
- Diagram: label "template models from data", pill on band:EXPERIENCE.

## D172 — The record catalogue knows the new run files and reads kinds by shape
- Sources: D47, handoff changes 5 and 10.
- Decided: `records.py` has rows for `timing.json` and `deliverables.json` (open objects) and `autofix.json` and `input_cuts.json` (lists), checked against mock runs of the vendored J2; `stage-<kind>.json` reads the kind by shape (`stage-[a-z][a-z0-9_]*`); `<name>.json` and `site/<name>-v<N>.json` is a type's data file (`ArtifactData`, `artifact` an `ArtifactName`, each section a bounded JSON object) when the file carries the `artifact-schema/` key: the route is last and matches by name shape, and a file of that shape without the key is "not in the catalogue" (left alone in log mode, refused in strict mode), so a new file name is still found. `style.json` is an open object (the page type's style guide is data). `RegisteredWorkflow` and `ProposedWorkflow` gain `work_kind` (J2's `kind`: `build` or `audit`; the model's own `kind` is its discriminator) and `sections` (the section names a document workflow writes), read by `registered_from_j2` and `from_j2` and written back by `to_j2` under J2's keys. `RegisteredWorkflow.output`, `Evaluation.output` and `ArtifactData.artifact` are names by shape and default to `None` (not "website"); `to_j2` omits `output` when it is `None`.
- Why: strict mode refuses unknown files and every run of this sync writes the four new ones; the type literals go with the mirrors.
- Rejected: leaving the files to `UNCHECKED` (strict mode would not validate them); a name pattern alone for the data file (every unknown `x.json` would be refused with the wrong reason).
- Diagram: label "records: timing, autofix, cuts", pill on band:DEPARTMENT RUNTIME.
