## Reading an Outcome (contract for E6's runner)
ok = pass; ok + `changed` = J2 recovered, close `RECOVERED: <evidence>`; ok + `waived` = J2 accepted a concern, close `WAIVED: <evidence>`;
ok + `na` = does not apply; not ok = fail. So a waived outcome is ok=True (spec: "all ok or na: close, with RECOVERED/WAIVED").
## Decisions and deviations
- `Evidence` gains optional `saved` (record names saved this turn); None derives it by comparing `records` with `before`. `judge-gate`,
  `charter-stamp` and the three Audit checks need "saved this turn". `posted` messages MAY carry `after_reply` (replies seen when posted):
  `atom-rules` uses it, else a batch heuristic (a repeated rejected name starts the next batch).
- `charter-stamp` waived = stamp fails and the `Charter accepted after two attempts` post is in the turn. `judge-gate` below 0.80 is waived
  (spec: J2 does not fund, WAIVED), so it fails only when `plan_confidence` is missing. Round scores are the minimum workflow score per round.
- `atom-rules`: the last reply drew a rejection -> recovered `dropped <names>` if any workflow is left, fail if none is or the turn errored.
- `turn-posted`: a message with no `next` is fine; one with a `next` must be in `HANDOFFS`, `auto`, or contain `Hand-off by code`. On a
  `dispute` turn J2's own `ROUTES` also count (`J2_ROUTES`, parity-tested): Audit disputes to Adaptation, which `HANDOFFS` forbids (found by
  running a mock Brew Lab through the checks).
- `within-budget` / `price-kept` read amounts as the reply states them (`envelope.money_limit`, `cost`, `estimated_resources.money`); the
  rate card is run state a pure check cannot see. J2's own note `GRANT of N exceeds the remaining budget (M)` overrides when present. `proposal`
  (J2's handoff kind for the price turn) is accepted as `price`.
- Imports `j2_check.design_problems` / `problems` directly (J2's own measurement); `stamp_check`, `workable_problems`, three regexes and `J2_ROUTES` are
  ports, tied to the vendored `j2.py` by parity tests. Strings J2 posts are pinned by running J2 (`_reject`, `_kept_price`, `_audit_findings`,
  `_audit_rubric`) or by source grep (4 strings).

  map the J2 handoff kind (`proposal`) to the template kind; replace `{question_message_id}` for `answer-recorded`; wrap `REGISTRY.run`.
