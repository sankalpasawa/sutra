# E6 as built: function-node layer (ids, declare, check runner, layer, factory)

## Built (`sutra_app/engine/fnodes/`, tests `tests/engine/test_engine_fn_{declare,checks,layer}.py`, 68 tests, about 1 s)
- `ids.py`: `AtomIds` (counter per (run, node) from 1, every open consumes one, a bad id part spends none), `node_id_of`, `run_overhead_id`.
  Ids come only from the library's `atom_sid`, `function_atom_id`, `function_node_id`, `overhead_atom_id`.
- `declare.py`: `declare(turn, spec, workflows=, work=, question_id=)` and `declare_question(...)` give an `AtomDraft`: template by
  (function, kind) else `generic`; floors first (`reply-valid` for llm with a reply family and kind, `turn-posted` for llm and bash, none
  for manual), then the template's checks; each check carries the registry sentence as `text` and `relevance`.
- `checks.py`: `TurnBuffer` (deep copies at hook time, `after_reply` on posted messages), `CheckRunner.evidence/round`, `Round`, `CheckRun`.
  Exit 0 ok or na, 1 fail, 127 cannot run (unknown name, bad args, exception, evidence that cannot be built). `RECOVERED: ` / `WAIVED: `
  go in front of the evidence of the check that was repaired or accepted. A fourth round raises `ValueError` (the layer never asks).
- `layer.py`: `FunctionNodeHooks(EventHooks)`, `factory`, `WRITE_TERMS`, `writable_records`. Hook behaviour is function-nodes.md 5.2 exactly.
  Every transition is one `atom` event (body = the gate's `Checked[Atom]` JSON, card, ledger at the end); all lines parse with ORCH's strict `RunAtom`.

## Decisions and deviations
1. `factory(writer, notify, validator=None, node_context_file=None, task=None, *, environ=None, specs=None, clock=)`; `task` is the `TaskSpec`
   (or a dict) and only seeds run and department ids. Mode `off` returns plain `EventHooks`, `enforce` and unknown words raise `ValueError`,
   and so does an unloadable spec file (`FunctionSpecsError` becomes `function specs: ...`).
2. Reply phase runs only checks whose registry phases include `reply`; the rest answer `deferred: judged when the turn ends` (exit 0).
   At turn end EVERY declared check is judged on the whole turn, reply-phase ones again on the last reply (the library wants one result per check).
   So a bad reply costs one try at once, and if the turn still ends on a bad reply it costs a second one: 3 tries are never exceeded.
3. A third failing close (reply or turn phase) abandons at once with code `verify_failed`; at turn end a failing round always fails the close first
   and then abandons (event order: `verify_failed`, `abandoned`). `CheckSpec.tries` is documentation only; the runner does not read it.
4. The manual atom always belongs to Identity (only Identity reaches the owner) and uses the spec's `answer` template; its question id is the
   id of the turn's `ASK_REQUESTER` message (fallback: the last message of the turn). The owner's `user` message runs `answer-recorded`.
5. `Seen` is passed on every close and abandon: `work` is llm when the turn made an agent_turn call, else bash (notes `declared bash, did llm`),
   `model` is the first call's model. Manual atoms pass an empty `Seen`.
6. `FunctionSpec.writes` is prose, so `WRITE_TERMS` maps each phrase to the record files it implies (goal, workflows, audits, realization,
   conflicts). Only those five files are judged. The table is a first guess: E7's golden decides whether to adjust it before scope goes hard.
7. A turn whose handoff has no kind is declared as kind word `turn` (generic template). J2's price handoff `proposal` picks the `price` template.
8. `declare` predicts schedule as bash when `workflows.json` is absent or holds nothing registered or held; `work=` lets a caller ask for the other kind.
9. When the node's latest call has no usable reply (`CallInfo.reply` None) the evidence holds no replies at all, so `reply-valid` fails with
   "the call has no reply" instead of judging an older reply. Cost: `atom-rules` then sees no reply either (na). Rare, accepted.
10. `abandon_open(status)` is public for the host's stop and SIGTERM path (there is no hook for it). Hook bodies are serialised by one RLock.

## Known limits and follow-ups
- E3 (host): call `hooks.abandon_open("stopped")` on a stop line and on SIGTERM; pass `task` to the factory; the hooks are not given the
  factory's `specs`/`clock` arguments there.
- E7: the golden decides `WRITE_TERMS` and whether `reply-valid` accepts every reply J2 accepts (a refusal shows up as `verify_failed`, harmless to the run).
- J2's builder atoms (`atom/1`) are not touched here; `Evidence.owners` holds only the layer's own atoms.
- No `node` event, no `usage` event and no `step` event is written here (StatePublisher and the router sink own them).
