# L6 as built: node family, graph edges, function-spec plug-in

Built in `sutra_app/library/node.py` (library design section 8; S2-models-02/03, S3-web-04, S4-fnodes-14): `Node` (abstract, family
`node`), `StructuralNode` (root, department, division, step), `FunctionNode` (abstract) with `IdentityNode` ... `AuditNode`,
`NodeStats`/`NodeTokens`, `GraphEdge` (family `edge`, seven kinds) with `EdgeSource`, `edge_id`, `make_edge`, `derive_edges`,
`HANDOFFS` (+ `hands_to`, `may_hand_off`), `check_graph` (G1 to G5), `step_node_id`, and the spec models `TaskKind`, `CheckRef`,
`AtomTemplate`, `FunctionSpec`, `FunctionSpecs` (family `function_specs`), `load_function_specs`, `new_function_node`,
`refresh_function_nodes`. Tests: `tests/library/test_lib_node.py` (90 functions, 192 cases, 0.4 s), builders in `factories_node.py`
(`graph_of(chart)` gives a graph that mirrors a chart; `toy_specs()` gives five valid specs).
## Wiring (the L1 review's follow-up)
Importing `node.py` calls `REGISTRY.bind_function_specs(load_function_specs)` and `REGISTRY.bind_check_arity(check_arity)`, so a bare
`REGISTRY.verify_refs()` loads `specs/function_specs.json` and checks every task kind's reply family and kind and every template check
name and argument count. Tests point `node.DEFAULT_SPECS_PATH` at a tmp file: a clean set returns `[]`, a broken one returns all five
violation kinds on the right paths, a missing file raises `FunctionSpecsError("missing")`, and all five functions are looked at.

## Deviations from the specification
- `GraphNodeId` suffix after the dot is `[a-z]{1,16}` (spec `[a-z]+`): rule 3 wants a finite width. `Node.ts_created/ts_updated` default 0.
- `GraphEdge.from_id/to_id` also refuse `>` and whitespace (the id would be ambiguous); `EdgeSource.value` is a bounded string.
- A step node's id must match `s-` + 10 hex digits; the sha1 itself is not re-checked (`step_node_id` builds it). Kept loose so a store
  or test with another task key does not fail; follow-up: the graph store should always use `step_node_id`.
- `AtomTemplate.goal` may name only `{function} {kind} {step_label} {task}`; any other brace is refused at load (declare would KeyError).
- `FunctionSpec` also refuses duplicate template names and duplicate task kinds. `TaskKind` reply fields default to "" (no reply).
- Additions beyond the spec: `derive_edges`, `make_edge`, `edge_id`, `hands_to`, `may_hand_off`, `FUNCTION_NODE_CLASSES`, `FunctionSpecsError`
  (codes missing, unreadable, too_large, not_json, invalid + violations; file cap 1 MiB).

## Decisions
- Node validators report every problem at once through a `_problems()` hook that subclasses extend (one validator in `Node`).
- `check_graph`: G1 also flags a root/department/division node the chart lacks, and duplicate node ids; G4 is strict only for `contains`
  (equal to the chart); a given `has_function`/`has_step` edge must match the node fields, a missing one is not reported; G5 considers
  stored kinds only. `parent_id` of chart nodes and `label` are not compared with the chart.
- Function node `label` is the capitalised function name ("Priority"), as the design's example shows. `refresh_function_nodes` keeps
  `version` and `ts_updated` (the store bumps them) and skips nodes already at or above the spec version.
- `wait_on` is any bounded string (spec says `S?`); the design lists `you`, a function key or a builder id but a closed list would break events.
- The `step_ref` role part of `team:<role>` is 1 to 34 characters of letters, digits, space, `_`, `.`, `-` (J2 names no role set).

## Known limits and follow-ups
- `specs/function_specs.json` is L10's file; until it merges, `REGISTRY.verify_refs()` with no argument raises `missing`. L8's full-registry
  test should assert that the call checked a non-empty set (the loader never returns an empty `FunctionSpecs`).
- Chassis owner: `[tool.setuptools.package-data]` still needs a glob for `library/specs/*.json` (design 8.4).
- ORCH graph store: build edges with `make_edge`, step ids with `step_node_id`, pass `derive_edges` output plus stored edges to `check_graph`.
