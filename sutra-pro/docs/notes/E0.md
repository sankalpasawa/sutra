## Deviations from the specification
1. `atom` events carry `outcome`, `card`, `ledger` NEXT TO `node` and `atom` (function-nodes.md 6.1), only for `work-atom/0.3`; `ledger` is null while open.
2. In mock mode `PROVIDER`/`MODEL` stay None whatever the port's `describe()` says (J2's run files had null there), and `LAST_META` stays empty.
3. A real (non-mock) empty reply raises `EmptyReply` (J2's providers did); J2's provider code, `llm.subprocess` and `llm._run_claude_cli` are gone.
4. `EngineSettings` has bounds the design does not list (>= 0 or 1, budget <= 100000 as ORCH checks); env words true/false/yes/no/on/off are
   accepted and a word that means none is an error where J2 read it as off (or on). Unknown words for output and send_mode are errors, not J2's fallback.
5. `TaskSpec` also reads `schema` (None or `run-spec/1`), checks run ids as ASCII `j2-[A-Za-z0-9_-]{1,120}` and refuses a blank `user_text`.
6. The Brew Lab form of "allowance is None" is proved at the shim (`ask` has no allowance parameter; every request has None): no vendored J2 yet.
7. conftest: `clean_env` also removes the engine's SUTRA_ switches; extra fixtures `make_run_dir`, `llm_reset`. `-m` unlocks `slow` only in
   this conftest: `tests/conftest.py` (not mine) still wants `SUTRA_SLOW=1`.

## Decisions
- `ScriptedPort` row = the stub connector's (provider stub, model scripted, tokens = chars // 4, usd 0.0, how stub), a dict with `UsageIn`'s keys;
  `call_ref` is `<run>:<call_no>` or `r:<n>` (a counter per port); a failed request leaves one failure row; `close()` ends a delayed request.
- `EventWriter`: one `os.write` per line under an RLock (a signal handler can still write `run.ended`), ASCII JSON (U+2028 safe), nothing after
  `run.ended`, files 0600, the run folder is never made. `EventUsageSink(default_atom=)` charges an atom-less row to the run overhead key.
- Builders refuse what the design forbids (a function node's status is one of the first five words, `who` never `user`, `wait_on` words, ...).
- `EventHooks`: `say` before validation (a strict rejection still leaves the message visible); extra trace types `run.error`, `addendum.error`.

## Known limits
