# J2S4-V as built: live verification of J2 sync 4 (lane V)

No code was changed. The integration tip `5624afb6` (all code lanes merged) was run for real: the three pin checks, the real claude connector on a
copy of an installed 0.2.1 data folder, an offline full run, and the pages in the built-in browser pane. `<scratch>` stands for a throwaway folder
that was removed at the end. Every server was started from this worktree with `scripts/py -B -m sutra_app --data-dir <folder> --no-browser --port <free port>`
and a throwaway `SUTRA_TOKEN`; both were stopped (SIGTERM, then no process and no listening port left).

The real data folder `~/.sutra-pro` was never written or signalled. It is in WAL mode, so the copy was made with
`sqlite3 "file:~/.sutra-pro/db.sqlite3?mode=ro&immutable=1" ".backup <scratch>/copy/db.sqlite3"` (a plain open would create `-wal` and `-shm` files beside the
real database), then `cp -R` of `departments/`, `connectors/` and `library/`, and the copied `connectors/workdir.json` deleted. Proof: name, size and mtime of all
388 entries of the real folder listed before the copy and after the last step are identical, and no `-wal` or `-shm` appeared.

## Defects

- **D1 (low, a click target): the attention pill covers J2's own controls in the Simple view.** File `sutra_app/ui/static/css/sutra-panel.css`, lines 32, 37 and 41 to 44 (`.apillhost`).
  Symptom: with a run in the Simple view and any org-wide need showing (the real copy has one: a stale team question), at 1280x860 the pill (x 1172 to 1264, y 823 to 844) sits over the lower right of the "Open full view" button
  (x 1111 to 1251, y 805 to 841) and `document.elementFromPoint` at the pill's centre returns the pill, so it takes the click; at 375x812 the pill (`top: 58px`) sits over the lower edge of the "Decide for me" switch (y 37 to 67) and the dark-mode button (y 35 to 69).
  Repro: open `/d/<team>/?run=<finished run>&view=simple` at those sizes with any "N needs you" present.
  Probable cause: the E3 fix lifts the pill above J2's Chat button only for `body:not(.simple)` at 901 px and wider, and the phone rule (`top: 58px`, "under the header") predates sync 4's second toolbar row in the Simple view; neither clears the Simple view's own bottom-right button or that row.
- **D2 (low, data from the older engine): the newest run made by 0.2.1 shows an empty plan.** File `sutra_app/engine/views.py`, `state()` / `effective_snapshot()`.
  Symptom: on the copy, the team's page (Simple view) says "The plan: No parts yet." and the team's `status` is `waiting` although the task is `done` and its process is gone.
  Repro: GET `/api/state?dept=app-development` has no `studio` block (`studio.parts` empty); GET `/api/state?dept=app-development&run=<that run>` (the saved path) has 5 parts.
  Probable cause: for a live-mode context whose process is gone the published snapshot is returned as it was published, and the old engine never published `studio`; the saved path builds it (`j2.saved_snapshot_dir`). A fallback that builds `studio` when it is missing would close it. It heals itself with the team's next run.

- **D3 (known, pending lane G: the docs gate is red on the tip).** `scripts/py scripts/check_docs.py` exits 1: `docs/ENVIRONMENT.md: the variable J2_DECIDE_FOR_ME has no row`;
  `pytest tests/test_docs.py tests/test_ownership.py`: 12 failed, 60 passed (the ownership test passes, with this note in the tree).
  Cause: lane B added the engine setting `decide_for_me` (env `J2_DECIDE_FOR_ME`) and asked lane G for its row (`J2S4-b.md`); `docs/ENVIRONMENT.md` was not touched on the integration branch.
  Checked in memory only (nothing written): adding the one row `| `J2_DECIDE_FOR_ME` | `decide_for_me` | `0` | no | yes | ... |` after the `J2_TEMPLATE_LIBRARY` row leaves the checker with no problem, so this row is the only thing it reports. The 12 failing tests count problems or expect the real document to be clean (one fails on `assert (2 ...`), which the row explains; they were not re-run with the row, since no document was edited in this lane.
