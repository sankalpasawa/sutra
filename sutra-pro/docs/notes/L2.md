# L2 as built: org chart and chart changes

Built in `sutra_app/library/org_chart.py` (library design section 4, S2-models-01 and -04): FunctionIds, OrgNode, OrgEdge, OrgChart (rules V1 to V6,
sorted edges, `node`/`parent_of`/`children_of`/`subtree`/`department_of`), `seed_chart`, NewNode, the five ops, ChildMove, ChartChangeRequest,
ChartChange, `derive_kind`, ChartChangeResult, LinkPlan, ChartChangeInvalid, `slug_id`, `apply_change` (C1 to C11), `carry_links`, `resolve_alias`.
`CHART_OPS_TRANSPORT = "union"`; `ChartOpFlat` is not built (the live check decides). Tests: 3 files, 147 functions, 217 cases, 2.5 s.
`tests/library/factories_org.py` has the builders for any later test: `make_chart`, `six_node_chart`, the op builders, `make_change`, `apply`, `refused`.

## Decisions where the design is silent
- Violation paths: `""` (stale_base), `reuses.<i>`, `ops.<i>` + `.node .to_parent .into .sources.<j> .node.parent .parts.<k>.name .moves.<m>.child|.to`,
  and `chart.<loc>` for `invariant` (the place in the chart that would result). OrgChart validators raise one error per violation at its own place.
- Depth is the number of edges below the root: a department is 1, divisions may reach 6. Nodes cap at 500, edges at 500, ops at 8.
- The helpers return ids, not nodes (`parent_of`, `children_of`, `subtree`, `department_of`); an unknown id gives None or `[]`. Order is the order of `nodes`.
- C12 (refs) is checked on ChartChangeRequest, so ChartChange inherits it and a bad model reply is refused by ReplyParser with retry text; the kind and
  reuse checks are ChartChange's own; all are reported together.
- ChartChangeRequest is registered as the payload `chart_change_request` so `ReplyParser.parse(...)` and `REGISTRY.transport_schema(...)` serve stage B.
- `reuses` is checked against the chart before the change for every kind, not only reuse. A stale change gives only `stale_base`.
- Sibling names clash after NFKC, casefold and removing all whitespace. The rule also covers children moved by a merge or a split (`duplicate_name`;
  the table lists no code for that: rename first, ops run in order). Rename of the root is `unknown_node` (the table says so).
- An op that needs the ref of a failed add is skipped without a second violation. A failed op changes nothing (merge and split run on a scratch copy).
- `moved` = every node whose parent changed (move, children taken in by a merge, split moves), never a node added by the change. `merged` = the
  merged-away ids (the keys of `aliases`, in merge order); alias chains are not collapsed. A node made and merged away in one change is in `ids`,
  `aliases` and `merged` but not in `added`. A rename appears in no list.
- `new_id(kind, name, taken)` gets a frozenset (chart ids plus ids made so far); a taken or malformed id is an `invariant` violation. `slug_id`
  makes hyphen-only ids of 2 to 40 characters (kind-prefixed when the name has no leading letter), so they also fit the department URL rule.
- `carry_links`: the order of `links` decides which merged node gets `move` when the target has no session; a link for a node that is neither in the
  chart nor merged away, or one session linked twice, raises ChartChangeInvalid (`unknown_node`, `bad_links`); `resolve_alias` raises `alias_cycle`.
- Additions: `ChartChange.from_request(...)`; `ChartChange.kind` has no default (code must set it). The C9 checks (`ids_lost`, `functions_changed`)
  cannot fire through valid ops; they stay as a defence in `_preserved_problems`, tested directly and by a patched call.
- The transport schema is 3.4 KB (the prototype's 2.3 KB had no text): class sentences and four field hints are what the model reads. Under 4 KB.

## Known limits and follow-ups
- L8: `all.py` must import `org_chart`; `docs/schemas/` will gain `org_chart`, `chart_change` and `chart_change_request`; the live test can use
  `six_node_chart()` from `factories_org` (the six nodes of S2-models-04).
- ORCH: wrap `new_id` to widen `taken` with every id ever stored (library `apply_change` alone could reuse a retired id); pass `links` in old-chart
  order; `ChartStore.check` can show `retry_text_for(exc.violations)` to the agent; a made `ChartChangeResult` for a reuse holds the same chart object.
- `apply_change` builds and validates the whole new chart (O(n * depth)); fine at 500 nodes.

## Mutation check
12 hand-made mutants (depth off by one, V4 inverted, MAX_OPS, swapped path arguments, cycle check deleted, early return dropped, case-sensitive
names, carry_links branches swapped, moved filter inverted, derive_kind all to any, edges unsorted, bad_target branch deleted): all killed. A stdlib
`trace` run then showed 11 lines of org_chart.py never executed; 4 tests were added, 3 dead guards were rewritten, and every line now runs.
