# L9 as built: J2 wire documents (`sutra_app/library/wire.py`)

## Built
- Nine closed, strict, frozen payloads (all version 1) registered on import: `map` (map/1), `board` (board/1), `story`
  (story/1), `agent` (agent/1), `artifacts` (artifacts/1, artifacts.json), `artifacts_tree` (artifacts-tree/1), `realization`
  (realization.json, the whole planning record), `realization_plan` (the realization/1 schema = the record's `plan`) and
  `run_summary` (summary.json, budget `{start, granted, used, raises}` as `SummaryBudget`, S2-models-14).
- Tables for L8: `WIRE_PAYLOADS` (name => class), `WIRE_FILES` (map.json, board.json, artifacts.json, realization.json,
  summary.json => name) and `WIRE_SCHEMAS` (J2 schema string => name). story, agent and the tree are served, never saved.
- `Wire.wire()` returns J2's JSON back: only the keys that were set, `schema` first. Strings come back whitespace-stripped
  (the library config); keys are exactly J2's.
- Validators re-derive what J2 derives by code: unique node/entry ids, `has_board`, story numbers and recheck counts, agent
  `summary.calls` and conversation `count`, tree group `count`, condition tallies, status vs outcome sentence, budget raises,
  plan rules (factor source rules, research workflows, unique names, inputs exist), rounds numbered from 0.
- Tests: 67, about 6 s. Real engine output (site, PRD, board and plan scenarios) is run in a CHILD process (the engine's module
  state and J2_* flags must not touch the test process) and every document it wrote or served passes `GATE.check` and
  round-trips through `wire()`. The rest are hand-built documents broken one rule at a time.

## Decisions
- The spec of this package is one table row, so the shapes come from J2 itself: `j2_map.py`, `j2_board.py`, `j2_story.py`,
  `j2_agent.py`, `j2_artifacts.py`, `j2_realization.py`, `_write_summary`, docs/map-schema.md and realization-schema.json.
- Names are plain (`map`, `board`...), like `atom_view`; the J2 `schema` key is `schema_` with alias `schema`, the same
  allowed alias as `AtomView` (the L8 sweep must allow `schema` for them). Other aliases: `from`, `with`, `pass` (keywords).
- Free model output (checklist, judge faults, proposal_brief...) is a bounded JSON value (`MetaValue`).
- `realization_plan` has its OWN classes with wide bounds instead of L5's `Factor`/`PlanStage` (those are bounded to the
  model reply, 300/600 chars; a plan file written by a real model must not fail on length). Same rules, same enums except
  stage ids, which are free `^[a-z][a-z0-9_-]{0,39}$` strings like L5's `StageId`.
- Plans are not forced to have at least one factor/stage/workflow: J2 sends a plan with faults back once and keeps the last
  one, `plan_faults` says what is wrong. The realization schema's `minItems: 1` is therefore not enforced.
- Budget rule: `granted >= start`, each raise goes up, the last raise ends at `granted`. NOT `granted == start + raises`:
  a rehydrated run (rehydrate.py) starts with the earlier run's granted amount and an empty raise list.
- Map: a work/function/engine box is one class with optional kind keys; edge endpoints are NOT checked against node ids (J2
  leaves a step line dangling when a branch step is not listed).

## Mutation check (one pass)
24 breakages (flipped comparisons, dropped validators, widened bounds, removed alias/unset handling): all killed, no survivors.

## Known limits
- `test_lib_records.py` (L8) does not exist yet, so the acceptance command's second path cannot run; the gate runs the rest.
- Cross-document links (map vs artifacts rows, story vs board) are not checked; each document stands alone.
- Board entries with a document change (`artifact_update` with `doc`) and the `asks`/`uses` map lines come from code reading,
  not from a mock run (the mock only produces a builder question answered by a workflow).
