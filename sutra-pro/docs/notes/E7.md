# E7 as built: function nodes in a whole run (golden atoms, event contract, prompts unchanged, no usage without an atom)

## What was built
- `scripts/record_fn_golden.py`: runs the real engine host in-process (thread, mock mode, Chrome faked) on the Brew Lab brief given
  as a vague line ("a website for my cafe") that the Requester answers with the full brief, so Identity asks, the turn pauses and
  the manual atom appears. Run twice (layer on, `SUTRA_NODES=off`); writes the two golden files; `--check` re-records and diffs.
  Also the importable implementation (`run_scenario`, `atoms_golden`, `normalized_events`, `prompt_digest`) both tests use.
- `golden/fn_atoms_brewlab.json`: 31 function atoms in order (node, J2 step, work kind, checks, transitions, final display, ledger
  status, failing check), per-function summary, `layer.touches_miss` counts, usage counts per atom family, 29 prompt digests.
  `golden/run_events.jsonl`: the deterministic events of the layer-on run.
- `test_engine_fn_golden.py` (29 tests, ~4 s): prompts identical on/off and equal to the golden; same ending and `say` lines;
  each function has an atom of each kind it handles (incl. the manual atom); one atom per function turn, never two open per node;
  none open at `run.ended`; every atom has a check; ledger rows = terminal atoms; no `usage` without an atom, function-atom cost
  arrives while that atom is open, calls outside a turn carry the overhead key; atoms/events equal the golden; recorder round trip.
- `test_engine_events_contract.py` (34 tests): imports the orchestrator's `RunEvent` unconditionally; 14 builder samples, every
  line of a live run strictly, the library gate on each function atom body/card/ledger row, the golden file, negative cases.

## Decisions and deviations
- Hook wiring (Findings 1): tests reach the layer through a `SUTRA_HOOKS` adapter (`fn_golden_hooks`, put in `sys.modules`) that maps
  `spec=` to `task=` and passes a fake clock; the rest is the host's own path. An xfail test (`strict=False`) runs the default wiring.
- The prompt digest replaces J2's own wall-clock stamps (`2026-11-04T18:09:57`, the `t` of a check result in a builder prompt) by
  `<time>` before hashing; without it two runs of the same J2 differ, layer off versus off too.
- The golden event file keeps `run.started`, `say`, function atoms, `usage`, `run.ended` (fixed `at`, pid, usage seconds); `node`,
  `step`, `heartbeat` and builder `atom/1` views depend on the 250 ms publisher and J2's clock, so a live run validates them.
  The atoms file stores the failing check's name, not pydantic's text. The scenario "vague line, then the brief" gives the manual atom.

## Findings (for other packages)
1. BUG E3/E6: `Host._make_hooks` calls `factory(..., spec=<TaskSpec>)`, `layer.factory` names it `task`. The TypeError is swallowed
   (`publish.error`) and the host falls back to plain `EventHooks`: a default run has NO function atoms. Rename or accept `spec`.
2. E3: a `stop` line or SIGTERM ends the run without `hooks.abandon_open("stopped")`; the unanswered question's manual atom stays
   open at `run.ended` (xfail `test_a_stopped_run_leaves_no_atom_open`).
3. The mock's replies fail the strict reply classes: 9 of 31 atoms end `verify_failed`, all by `reply-valid` (Identity's intake on
   the answer, Adaptation proposals, Priority prices). This is the open measurement of the design; J2's outcome (`done`) is unchanged.
4. Write scope stays warn-and-log: the golden run has 12 `layer.touches_miss` lines (adaptation and priority save `conflicts.json`,
   identity saves `workflows.json`); `FunctionSpec.writes`/`WRITE_TERMS` must name them before it can go hard.

## Mutation self-check (one pass, copy in /tmp)
19 breakages (rebind/bind removed, ledger never, manual atom never, answer never closes, prompt addendum, touches_miss removed,
reply checks skipped, heartbeat extra field, outcome dropped, recorder variants, ...). 17 killed. Survivors: `run_status` no longer
abandoning and the stale-atom `replaced` abandon: no atom is open at those points in the mock run (E6's layer tests own them).

## Limits
- Not covered: a refused open, `run_error`, the publisher's ordering. The golden is the engine's own measurement (30 usage rows:
  23 function, 6 builder, 1 overhead), not a J2 comparison; after an intended change re-record and read the diff.
