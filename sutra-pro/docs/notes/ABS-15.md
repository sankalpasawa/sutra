# ABS-15 as built

`chat_composer.js` (`ChatComposer`): `create({api, sid, readFile, onChange, mode})` is a small controller (state, `setMode`, `addFiles`, `removeFile`, `send`, `stop`, `partial`, `reconcile`) that takes the api, the file reader and the repaint as arguments, so node tests drive it without a page; `bar`, `chips`, `streamRow`, `button`, `askBlock`, `providerOf` are strings in, strings out (escaped). Files are checked with `ChatSearch.checkFile`, read as base64 and sent to `POST /api/chats/{sid}/attachments`; Send posts `{text, attachments}` to `/direct`; Stop posts `/direct/stop`; the turn ends when an agent message newer than the owner's line is stored (`reconcile`), so a stopped or failed turn also ends (the server stores an error line).
Wiring: `node_panel.js` (a team chat: the toggle "Tell the team" / "Ask the model", the row under the messages, the Send button as Stop, `chat.partial` on the panel's own stream) and `home.js` / `home.html` (org chat: "Plan with Sutra" / "Ask directly"). `dept_ext.js` injects the script into the J2 page. The provider shown in the row is the pill's chosen one; with no runnable provider the box says so and does not send. CSS in `sutra-panel.css`.
Server (D115): `POST /api/chats/{sid}/direct/stop`; `/direct` accepts `cs_org`.
Found on the way: `SutraEvents.TYPES` did not list `chat.partial`, so no page could ever receive a partial (ABS-9's row was built but unreachable). It now lists 15 names (`events.test.js` updated).
Tests: `tests/ui/js/chat_composer.test.js` (15), `tests/orchestrator/test_api_chat_v2.py` (org direct, stop), `tests/e2e/test_browser_chat_composer.py` (real Chrome, fake claude and codex; opt-in with `SUTRA_BROWSER=1`). The typed blocks in the browser test come from an in-process stored reply, because the fake CLI's chat stream has no tool calls.
