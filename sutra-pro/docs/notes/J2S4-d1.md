# J2S4-d1: the seed sync (lane D, package D1; D144)

Branch `lane/sync4-d1`, from `feat/sutra-pro-j2-sync-4`, with lane A's A1 and A1b merged (the new seed: 157 files, 32 templates, 39 versions, 8 runs rows).

## Built

`sutra_app/ops/doctor.py`, the seed section:

| Name | What it does |
|---|---|
| `sync_seed_library(data_dir, seed=None, *, report=None)` | returns the templates added (`artifact/section/slug`, as before) and the versions added to templates the library had (`artifact/section/slug@vN`); fills `report` with `templates`, `versions`, `filled` (version -> provenance keys added), `skipped` (`[{template, version, why}]`) and `runs`. A data folder with no library gets the whole seed (copied beside it, one rename, as the engine does). Otherwise it runs under `<library>/.lock` (the file and `oslayer` calls of P10; waits `LOCK_WAIT_S`, 30 s, then `LibraryBusy`), re-reads the index inside the lock, and writes it once, last |
| the rule (`_apply_seed`) | per seed version, the library's state decides and the seed's number never changes: same spec sha anywhere = present (provenance filled in its row and its `meta.json`; a lost folder at the seed's own number is restored); a row at that number with another sha = `skipped`; a folder at that number with no row = adopted when its own `meta.json` has the sha, else `skipped`; a free number = folder copied (temp folder, then one rename) and row appended. A template the library lacks (no entry, or no folder) is the same rule over all its versions and is reported as a template. The seed's `runs` whose id is absent are appended |
| `missing_seed_versions(data_dir, seed=None)` | read only, no lock: what the sync would add or restore; the same code path with `apply=False`, so the doctor and the fix cannot disagree (a test pins it) |
| `sync_seed_once(data_dir, seed=None)` | the server's start-up sync: marker `<library>/.seed-sync` = sha256 of the seed's `index.json`; equal means nothing; else `sync_seed_library`, then the marker. Never raises (a warning in the log, no marker, the next start tries again). Returns the report or None |
| `SeedSyncError(OSError)`, `LibraryBusy`, `LibraryUnreadable` | the lock was held; `index.json` exists and is not an index (never replaced; an absent file or `{}` reads as an empty index, as J2 reads it) |

Callers: `sutra_app/orchestrator/wiring.py` `start_services` (only that function) calls `sync_seed_once` through `run_blocking` right after `db.migrate`; `sutra_app/ops/cli.py` `config sync-library` prints templates, versions, filled, runs and what it left alone (`--json` keeps `added`, adds `templates`, `versions`, `filled`, `skipped`, `runs`; a held lock or an unreadable index exits 1 with "nothing was changed"); the doctor's `library` check reports missing templates and versions with the fix `sutra-pro config sync-library`, and an unreadable index as a warning whose fix does not promise the sync repairs it. `engine/host/loop._seed_library` is untouched.

Tests (`tests/ops`): `test_seed_sync.py` (24), `seedlib.py` (helpers), `test_doctor.py` and `test_cli.py` (the seed tests no longer hard-code 26; new check and CLI cases).

## Measured

- On the shipped seed, a library as an install had it before sync 4 (derived from the seed: 26 templates, no provenance, no runs) gains 6 templates, 5 versions of 4 templates, provenance on its 26 versions (`business`, `made_by.date`, `mock`) and 8 runs, and its `index.json` then equals the seed's byte for byte; a second sync writes nothing (not even a rewrite of the index).
- Time: 47 ms for a whole seed, 36 ms for that sync, 7 ms for a sync with nothing to do, 5 ms for `missing_seed_versions`, under 1 ms per `sync_seed_once` with the marker in place.
- Nine deliberate breakages of the code (overwrite a present key, no lock, a taken number not skipped, an unreadable index swallowed, no marker, a copy in read-only mode, the same spec at another number re-added, no meta fill, no runs) were each caught by a test.
- Runs: `tests/ops` + `tests/orchestrator/test_startup.py` + `tests/integration`: 638 passed. Before the start-up change of decision 5: `tests/orchestrator` all green, `tests/integration` + `tests/e2e` + `tests/contracts` 198 passed 6 skipped. `tests/engine`: 11 failures, none in this lane's files or code (see Left).

## Decisions and deviations (for lane G's pills)

1. The seed's `runs` is an object keyed by run id (J2's `collect` writes `idx["runs"][rid]`), not a list of rows: runs are added by id, and a library `runs` that is not an object is left alone and reported in `skipped`.
2. What is not provenance is never touched: `used_by` (22 old versions have more uses in the seed than an install's own) and the template-level `description` (changed for 4 templates) keep the install's value.
3. A `meta.json` is filled only when its own `sha` is the row's: a file that does not hold it (an owner's edit) is left alone and reported.
4. An index that is not an index raises (`LibraryUnreadable`, an `OSError`) instead of returning an empty list: the CLI exits 1, the start logs it, the doctor warns. The old code replaced such an index by one rebuilt from the seed, which dropped the owner's entries.
5. A start with no library seeds the whole seed and writes the marker (the design's literal reading), so the Library page of a new team has the seed's templates before any run; the engine's own first-run seeding stays. A library the engine created has no marker: its next start does one cheap no-op sync.
6. `filled` is a dict (version -> keys added); a skipped seed version leaves the seed's runs rows pointing at the owner's version of that number (never renumbered, by D144).
