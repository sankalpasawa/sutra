# L3 as built: goal, department, evaluation, chat message meta

Built (library design sections 5 and 10, S2-models-14 and -15): `goal.py` (Question, TbcAnswer, ToBeConfirmed, GoalDraft, SiteGoalDraft, DocGoalDraft,
the stored SiteGoal and DocGoal = family "goal", `goal_kind`), `department.py` (Department), `evaluation.py` (Evaluation base, Finding, RubricResult,
ConditionResult, LldComparison, ResultEvaluation, RecheckEvaluation, PlanEvaluation, RunReview = family "evaluation"), `chat.py` (MessageMeta, RunMessage =
payload "run_message", `META_KEYS`, `BASE_KEYS`). 4 test files, 106 functions, 226 cases, 1.1 s. Every statement runs (a `sys.settrace` pass).
Checked against J2 33aeeda itself: the flow-test scenarios were run in mock mode in a scratch copy of J2 (16 runs) and every record validates: 19 goal.json,
41 audit entries, 154 conditions, 1,276 chat lines, 19 reviews, 1 recheck. The one refusal is a hand-built fixture of `workable_unit` (all_pass true over
failing rows). Of the 114 saved older runs only legacy vintages fail (46 audit entries with no id or verdict, 28 goals with `open_inputs`, 4 with
`dropped_by_requester` but no `charter_items`, 5 chat lines with keys `j`, `check`, `ok`). Fixtures in the tests are trimmed copies of those files.

## Deviations from the specification (J2's code or data showed the design incomplete)
- Bounds: a done-when item may have 600 characters, not 400 (J2 wrote 412 to 454 in 6 of 84 runs); every copy of an item (charter_items, core_items,
  dropped_by_requester, ToBeConfirmed.criterion) takes the same bound. Spec fields typed plain `str` got bounds (all in the code, one place each).
- Finding: verdicts add UNPAID and WITHDRAWN; `pass` is optional (an extra issue has none), checked only when present: true exactly for PASS,
  PASS_WITH_WARNING, WITHDRAWN; new optional keys `forced_test`, `real_verdict`. Finding ids stay `F-...` (all 125 extras seen follow it).
- RubricResult: verdicts add BLOCKED_BY_EVIDENCE and WITHDRAWN; carries `item`, `criterion`, `rubric`, `severity`. ConditionResult carries `text`, `check`
  (a name or a list), `assumptions`. ResultEvaluation adds `output`, `read`, `lld`; `results` may be empty (J2 writes `bool(results)`, J2:8968).
- `all_pass` follows J2: results, rubric rows and blocking conditions decide, an empty result never passes; after a WITHDRAWN row only the rows count,
  because J2:5080 recomputes it that way. PlanEvaluation.weakest is optional (None when nothing was lost); RunReview keeps `raw` and defaults the lists.
- Stored goal: a fact to be confirmed may belong to an item in `dropped_by_requester` (the owner override leaves it, J2:3399). DocGoalDraft accepts
  `site_name`, `business_type`, `visitor_needs` (J2's mock PRD charter carries them; transport-optional); DocGoal adds `chain`. `goal_kind` is new.
- MessageMeta has 60 keys: section 10's 52 plus 8 an AST scan of j2.py 33aeeda found (`forced_test lesson_test lesson_used lessons_offered playbook_used
  playbook_changes playbooks_offered board_read`). The scan: keyword arguments of calls to post, _say, _reply, _ask_user, and the dict() meta of J2:6306, 6411.

## Decisions
- SiteGoal/DocGoal are `(Record, _StoredCharter, Draft)`: a stored charter is still a draft. `kind` is redeclared; validators report every problem at its own place.
- A field called `register` collides with `ABCMeta.register`: pydantic warns and gives a subclass the method as the default. The warning is silenced where the
  class is made and RunMessage declares `register` again (a test pins both; no alias, so design rule 7 holds).
- MessageMeta's canonical JSON leaves out unset keys (a wrap serializer), so a stored message carries only its meta. Values are any JSON, 32 levels deep.
- Department.home_dir is only checked to be a relative path inside the data dir (no `..`, no `.` or empty part); `departments/<id>` is the writer's job.

## Known limits and follow-ups
- L8: `all.py` imports the four modules. goal.json and J2's audit entries have no `kind`: add `goal_kind(g)` and `"kind": "result"` before `GATE.check`
  (a recheck entry has its own). The first line of chat.jsonl is a header `{"meta": true, ...}`, not a run_message: skip it. ConditionResult has no family:
  validate `conditions*.json` with a TypeAdapter. The AST scan test should expect the 60 keys; `register` is a field, not an alias, so the allow-list is unchanged.
- Strictness: an extra issue keeps the model's own id unless it collides (F-... is what the prompt asks); a model that invents another id is refused in strict mode.
- ORCH: `chat_message.meta` can default to `MessageMeta()`; `Evaluation` is abstract (not registered), so is not a kind.

## Mutation check
12 hand-made mutants in one pass (core rule flipped, tbc item off by one, owner-dropped item, constant 600 to 500, `..` allowed, WITHDRAWN not passing, pass
check inverted, empty result may pass, warning condition blocks, plan gate `>=` to `>`, serializer keeps nulls, `register` not redeclared): all killed.
