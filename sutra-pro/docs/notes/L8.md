## Deviations from the specification
- `gate_record` returns `Checked | list[str] | None`. In `log` mode a rejection returns the warning strings (`record_rejected <file>: ...`),
  because `engine/hooks.py` turns a returned list into `record.warning` trace lines: that IS the `record_rejected` event, and the hook
  cannot be changed from here. A one-document file returns its `Checked`; a list file (rows) returns None; an unknown file is None (log).
- `all.py` does NOT call `REGISTRY.freeze()` (L1 note said it would): `orchestrator/records.py` registers four families after it and
  must not be imported by the library; whoever composes the app calls `all.freeze()` after both. `all.verify()` = `verify_refs()`.
- `wire` is imported plainly (L9 is merged), not inside try/except. `write_paths.txt` marks `tasks.py` `pending` (ORCH-6 is not merged):
  skipped while missing, scanned as soon as it exists. The allowlist lines carry a `gated:`/`read:` tag; `gated:` is verified by an AST walk.
- The drift test runs the export in a child process: other tests import the orchestrator's families into this process's REGISTRY.
- `docs/schemas/templates/` is written by `templates.write_generic()` (L7 asked for the export to call it; `export.py` is L1's).
## Decisions
- Files with no closed model get bounded open JSON (`run_file.*`: 500 keys, 32 levels): documents.json, sections.json, stage-*.json,
  report.json, change.json, schema.json, the chat header line and J2's `deed-send-record` receipt. outputs.jsonl, template_calls.jsonl,
  board.jsonl, rendered documents and `model.py` are `UNCHECKED` (never passed to a hook, no model) and accepted in both modes.
- `<kind>.json` (`artifact_data`): each section is judged by the library's generic section model on its generic fields only, as J2's own
  `j2_template_lib.validate` does, because a specialised template adds fields of its own (J2_TEMPLATE_LIBRARY=1).
- Receipt is told apart by value (`evidence` vs `checks`), not by `model_fields_set`: the gate re-reads canonical JSON, which holds every key.
  Every record is read after one JSON round trip (tuples become lists; NaN/infinity are `not_json`).
- Router: unknown family or version on POST is 422 (3.6: GateError is 422), on GET 404 `unknown_schema`; oversize 413 `payload_too_large`
  (raw body over 1 MiB + 8 KiB is refused unparsed); the body is parsed by the router so every error is the orchestrator's envelope.
- Sweep (L1 review): unbounded str/list and non-keyword aliases are checked over the 85 library classes; allowed aliases are `schema` on
  AtomView and the seven L9 wire documents. `verify_refs()` is shown to have looked at 5 specs / 20 check references (spy on the arity function).
- Parity allowlist: one disagreement, `required: "true"` (J2 lax accepts, library strict). Transport shas of all 22 models are equal.
## Known limits
- Not yet hooked: receipts.jsonl, calls.jsonl, memory/lessons.jsonl, outputs.jsonl are appended by J2 outside `save()`/`post()`, so only

- The live transport test (`SUTRA_LIVE=1`) was written, collected and its helpers run offline, never run against the real CLIs.
- A `size` rejection of a very large legitimate J2 file (> 1 MiB, e.g. map.json) would warn in log mode.
