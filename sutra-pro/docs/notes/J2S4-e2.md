# J2S4-e2 as built: the JS modules and the style sheet around the new page (lane E2)

Branch `lane/sync4-e2`. Owns `static/js/{output_pick,function_chat}.js` (new), `{agent_chats,node_panel,chat_view,dept_ext}.js`, `static/css/sutra-panel.css`, their
tests and this note. Design: `docs/design/j2-sync-4.md` D139, D147, D148, 4.3, 4.4. The page is the one lane e1 regenerates from `prototypes/j2` (the studio pin);
the modules were checked against that page in Chrome, not only against stubs.

## What was built

**E2.1, the two new modules.**
- `output_pick.js` (`OutputPick`): fills `#soutpick`, the first thing in the row under the start box. "What should we make?" with Let the team decide, Website,
  PRD document, Project work; a value outside them (an HLD) is added so the choice in force is shown. It reads `next_run.output` of `GET /api/engine/settings?dept=`
  (the team's default `effective.output` when the server does not say, `auto` otherwise), a change is `POST /api/output {type}` with the team, a 409 puts the old
  choice back, locks the select and says "The team has started; choose before the first message.", any other refusal puts the old choice back and says why. An
  archived team gets nothing built (and the CSS hides the placeholder).
- `function_chat.js` (`FunctionChat`): `hydrate(QA, who, run)`, called by page edit E21 from J2's own `loadFeed`, fills J2's `QA` list from the function's own chat
  session: the agents row of the run, the ask lines of its messages, a `q` line paired with the next `records` or `model` line. A question nothing answered says
  "No answer was stored."; a question in flight keeps its place and words and is not added twice; the stored entries sit after the feed's present records (`n`).
  It changes nothing, and answers false, on any failure, for the validator, and for a function with no chat of its own in the run. `askPath(dept)` is the route
  the node panel posts to.

**E2.2, the node panel and the lines.**
- `agent_chats.js`: a function's box under the pill has a Note / Ask switch (`boxMode`, `noteBox`); Ask is a question box ("Ask Audit", answered from the run's
  records and cannot change the run), `askRequest` builds `POST /api/ask?dept=` (null for an empty question, one over 2,000 characters, or a function that is not
  one of the five), `askProblem` says in plain words what a refused question means (401, 403, 409 busy, 400, network). A step's chat keeps the note box as it was.
- `node_panel.js`: the Ask box asks, shows "Asking Audit..." and is disabled while the answer is awaited (a second question is a 409), keeps the words of a question
  that could not be sent (and the words typed in each mode while the other shows), reads the messages again when the call returns, shows the answer's note
  ("No model is connected."), Enter asks, Shift+Enter is a new line. Once the run is over the note is gone and only Ask is left.
- `chat_view.js`: a line with `ask: "q"` is the owner's own line labelled "You asked"; `records` and `model` lines are the function's line with the label that
  says where the answer came from ("From its records, no AI call", "AI answer from its records"); every such line carries `data-ask`; `steer` is as it was.
- `dept_ext.js`: `chip()` fills `#deptchip` and `#deptchip-s` and sets the name as their title; a `chat.message` with `ask` raises no unread dot; the archived
  banner goes under the Simple view's strip. `DeptExt` and `DeptExt.helpers` export the same keys as before.

**E2.3, `sutra-panel.css`.** The rail's strip (`#rail .railhome`, the team's name as one short line), the Simple view's strip (`#sview>.steamstrip`), the node
panel hiding J2's chat panel and its button while it is open, the output choice, the archived rule extended to the studio's write controls (`#lform`, `#lbox`,
`#lsend`, `.schips`, `#soutpick`, `#sform`, `#sauto`, `#sautoland`, `#shome` beside the old ones), the Ask box, its switch, the question label and the source label.

## Found on the way, and fixed

- **The node panel had lost its bubbles.** The studio sheet scopes `.sb`, `.sb.me`, `.sb.team` and the answer buttons `.opts` to `#sview`; the drawer sits outside
  it, so its chat lines were bare text. `sutra-panel.css` carries the same rules for `.nmsg` again. Proof: the computed style of every element kind in five scenes
  of the panel (a team's chat, Audit's chat, Identity's Details, the Agents tab, a team's Details) under the previous J2 sheet and under the studio sheet: 7
  element kinds looked different before (both kinds of bubble, the option list, the text blocks inside them), none after (an ad-hoc Chrome probe, not committed).
- **The studio sheet breaks D122** (`transition: all` in three rules, 21 layout transitions, six keyframes on filter, box-shadow or left). `sutra-panel.css` has a rule
  for each, on transform, opacity and colour from the shared scale; keyframes of the same name replace J2's. `motion_css.test.js` now applies rules 1 and 2 to the
  sheets that are ours and rule 8 proves every offending declaration of the frozen sheets has its replacement. `contrast.test.js` judges the text of a rule that paints
  its own background (the owner's bubble, `--on` on `--accent`) by that pair, as its second test already did, not against the three surfaces.

## Deviations from the design

1. `POST /api/output` goes through `SutraCtx.api.post("/api/output?dept=...")`, not the page's fetch wrapper: the same request on the wire (token and team), with the
   uniform `ApiError` for the 409.
2. D139 says "disabled for an archived team", 4.4 says "not built": built nothing, and the CSS hides the placeholder as well.
3. The node panel offers Ask in a LIVE function chat only (4.4 says "only a function chat"); a past run's chat, which the Agents tab opens read-only, is read, not asked.
   J2's chat panel asks about a past run with its `?run=`, and the node panel shows those stored lines.
4. The Ask textarea is `.nask-text`, not `.nnote-text`: a finished run has no note field, which `test_agent_chats.py` checks.
5. `hydrate` reads only what is new since its last call (ids only grow), five pages of 200 at most per call, so a long session is caught up over a few calls; it takes
   `options {api, dept, feed}` as a fourth argument for tests (the page passes three).
