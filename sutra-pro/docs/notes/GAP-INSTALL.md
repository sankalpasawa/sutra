# GAP-INSTALL: install, run and remove the installed app (G17)

## Built
- `scripts/install_local.sh [--dry-run]`: `uv build --wheel` into `dist/` (or `$SUTRA_DIST_DIR`), `scripts/check_wheel.py`, `uv tool install --reinstall <wheel>` (non-editable, D88), then verifies the INSTALLED command: `--help`, `doctor --offline`, an offline start (`--no-browser --port 0`) that must answer `/api/health` within 20 s (`SUTRA_INSTALL_START_WAIT`), `GET /`, one chat message (202, then the turn ends), `sutra-pro stop` and the process gone. Prints the installed version and `~/.sutra-pro`. Exit 0 / 1 step failed (the server's last 30 lines are shown) / 2 usage.
- `scripts/uninstall_local.sh [--dry-run]`: stops a running server of the default data folder, `uv tool uninstall sutra-pro`, says that `~/.sutra-pro` stays. Not installed is not an error.
- `tests/release/test_installed_app.py`: 9 fast tests (syntax, `--dry-run`, usage errors, no uv, a bad wheel stops before the install) and 8 `slow` tests. The slow ones build the wheel from a COPY of the package (no `build/` in the checkout), install it into a temporary `UV_TOOL_DIR` / `UV_TOOL_BIN_DIR` with a throw-away `HOME` and a cleaned environment (no `SUTRA_*`, `J2_*`, `PYTHON*`, `UV_*`), and run the installed copy from another folder: `--help`, `doctor --offline`, an `-I` introspection (the code is under the tool folder; `function_specs.json` loads with the five functions; the seed library index; the five page files; agent templates; `policy.default.json`; no `pyproject.toml` beside the package so data and `.env` default to `~/.sutra-pro` and `~/.sutra-pro/.env`; `<data>/.env` when `SUTRA_DATA_DIR` is set, also in `config show`), then an offline server: health, Home page with token, chat message (401 without the token), a team and a task (the installed engine process runs and seeds `<data>/library` equal to the seed), `status`, `sutra-pro stop`, no engine process left, no traceback in `server.log`. Also: the install script run for real (stale wheel replaced, a hostile `SUTRA_CONNECTOR` ignored, temp folder removed, real data folder untouched, uv calls logged), and the uninstall script (command gone, data marker kept).

## Decisions and deviations
- The check runs on a throw-away data folder, also for `doctor --offline` (the spec's plain call would read or create `~/.sutra-pro`). The real folder is never touched by the install.
- `--port 0` (the OS picks a free port) instead of finding a port first in shell; the address is read from the server's "running at" line.
- The wheel is built into `dist/`, old `sutra_pro-*.whl` are removed first so the glob cannot pick a stale one; the `build/` folder setuptools leaves is removed when it did not exist before.
- The slow tests install from uv's cache with `--offline` first, then once through the network; where neither works they skip with the uv message printed.
- The server runs inside a subshell in the script so the shell's "Terminated" notice (a normal SIGTERM stop) goes to the log.
- Fake `uv` and fake `sutra-pro` shell stand-ins (in the tests only) cover the failure branches: a bad wheel, a server that never answers.
