# L4 as built: atom, lifecycle, ledger row, cards, display state, atom/1 view

Built as library.md section 7 and 14 say, in one module `sutra_app/library/atom.py`: `Atom` and `AtomDraft` with their parts, the 26 `CheckTemplate`
names (+ `check_arity`, bound to the registry at import so `REGISTRY.verify_refs()` judges function specs), `open_rules`, `open_atom`, `close_atom`,
`abandon_atom`, `Seen`, `Transition`, `Card` (`build_card`, `card`), `atom_display_state`, `LedgerRow` (`ledger_row`, `ledger_row_from_view`), `AtomView`
(payload `atom_view` v1) with `atom_view`, `link_views`, `run_views`, `validate_views` and friends. 4 test files, 136 functions, 270 cases, 0.4 s;
`factories_atom.py` (builders, `atom_from_j2`); `fixtures/atom/view_cases.json` (12 parity cases) and `build_view_cases.py` (run by hand, never by a test).
The parity cases are real atoms from J2's saved runs (3 runs, read only) plus edits of one, each with the view J2's OWN `atom_view` gave. Of 91 real
single-attempt passed atoms 79 match exactly, 5 differ only by an explicit `count: 1` (below), 7 hold a check with more than 8 targets (`Check.args` <= 8).

## Deviations from the specification
- `ExpectedItem`: kinds `heading`, `ids`, `send` added and an optional `met`. J2's document and deed atoms use those kinds and J2's code sets `met` (saved runs show both).
- `atom_view(..., *, stale=None, rechecked=None)` and `AtomView.wire()` (J2's JSON, stale/rechecked only when set): the Atom has no field for the board marks.
- A `..` in a file-exists or grep-count file is refused (`dotdot`) with or without an envelope; the plugin checks it only inside one.
- A refused atom keeps the draft but supersedes nothing: the gate rule `atom.supersedes_abandoned` would make a refused `bad_supersedes` atom unstorable.
- `Check` rejects wrong arguments of the 14 registry checks itself (test table: `value_error`); the plugin's three are open-time rules (refused `bad_args`).
- `Seen.note` is not stored and `Seen.work` leaves `how_kind` alone (S4-fnodes-03: nothing else changes). Event data carries `display` beside `state`.
- An envelope drift at close (an atom altered with `model_copy`) returns a refused Transition built with `model_construct`: a Transition validates its atom.

## Decisions
- `close_atom` wants each result's `attempt` == `atom.attempt + 1` (else `bad_results`); `pins_now` is compared only for entries given; exit 97 beats the runner's word.
- A refused close or abandon changes nothing and publishes no event, but has its ATOM REFUSED card. `abandon_atom` asks for the reason before the state (SA:373).
- `ledger_row`: closed shows the FIRST check, verify_failed the LAST failing one (exit 1 when none failed on record). `AtomError` is for misuse (open atom's row, bad code).
- `atom_view` ports `j2_schema.atom_status`; with no workflow given only attempt 3 is final (the library table), not J2's "workflow not running".
- A behavior item may hold 3 `wait` steps (spec); J2's own 3-second bound per wait is not repeated. The check arity of J2's nine types is 0 to 8 (the spec gives none).
- `ledger_row_from_view` reason: `details.reason`, the refusal message, notes, then for verify_failed the first unmet evidence, else a fixed sentence.
- Card rows follow the plugin (Done when, Done by, Limits, Using, Ref, Result, Proof, Output, Recorded, Why, Next, Reason); `goal` is the card's own field, so no Goal row.

## Known limits
- An explicit `"count": 1` of J2 is the default here and is not echoed in `defined_output`; J2's deed `how` is `{agent}` only, the view always writes kind, agent, steps.
- A check that could not run is exit 127 and a failed try (library risk 11): the view can say verify_failed where J2 says open.
- The library does no I/O: the caller hashes a `named-test` file (pin) and passes the current hash as `pins_now`.

## Follow-ups for other packages
- E6/E8: build `CheckResult(attempt=atom.attempt + 1)`; after the last failing `close_atom` call `abandon_atom(code="verify_failed")`; pass `Seen(work, model)`.
- ORCH: builder ledger rows keep J2's id in `LedgerRow.atom_id`; the table key `<run_id>:<id>` is the store's. L8: expect `("AtomView", "schema")` as the only alias.
