# E2 as built: the 30 views, the stdlib adapter, the API shape goldens

## Built (engine.md 4.6, 7.1, 9; J2 sync 2026-11-04)
- `views.py`: `Reply`, `MemoryPaths`, `RunCtx`, `Published`, `VIEWS` (29 names, `site` answers both rows 24 and 25 by `ctx.mode`; `site_saved` and
  `site_live` are the two functions), `live_state(run)`, `read_published(run_dir)`, `idle_snapshot(settings, memory, run_id)`. Modes live, saved, idle as in 4.6.
- `j2_server.py`: stdlib `Handler`, `RUN`, `HERE`, `VENDOR`, `DOCX`, `redact`, `secrets`, `route()`, `main()`. It builds a `RunCtx` per request from
  the in-process `RUN` (`live_state` only for the views that read the live run) and sends the `Reply`. POSTs route on `urlparse(path).path` [S3-web-07].
- J2 sync: `library_item` passes the run folder (the run's copy first, `source` and `saved`); `run_templates` answers `j2_template_lib.run_templates(d)`.
- `scripts/record_api_shapes.py` runs J2's own `Handler` (git archive of `--commit`, default 33aeeda, nothing written to the checkout) on one Brew Lab mock
  run with the template library, artifact schemas and board on, asks 30 GET routes in live, saved and idle and 7 POSTs, and keeps status, content type and
  KEY PATHS (maps keyed by ids as `*`, free-form model output not followed). `--check` re-records and compares (deterministic: two runs were equal).
- `tests/engine/golden/api_shapes.json` (recorded at 33aeeda). `test_engine_views.py`: 61 tests, 2.3 s.

## Deviations and decisions
1. `RunCtx` gains four optional fields after the spec's: `dept_id` (the additive state key), `commands` (the three POSTs), `here`, `vendor` (the
   stdlib page and d3 folders). `Commands` is a Protocol (`say`, `set_output`, `reset`); a POST without one answers 501. E4 passes the orchestrator's.
2. The POST handlers keep J2's validation and bodies (empty text 400, busy 409, output 200/409 with `output`, reset 200/409); only the act is injected.
3. `idle_snapshot` returns the 56 keys of `J2Run.snapshot`; `state` adds `saved: null` (live state has 57 keys; the design's "56" is the snapshot).
   `mock` in it is `llm.env_mock()` of the server process, `model` None (settings have no model; the next run's port is unknown).
4. Live `map`, `artifacts_tree`, `story`, `board` use the snapshot after the process-gone rule (a dead process is never drawn as running).
5. `read_published`: no pid in `live.json` means alive (nothing says it is gone). A torn or non-object `snapshot.json` reads as None.
6. Library item: the version is one path part `v<N>` in `q["version"]` (also `artifact`, `section`, `slug`); shot `n`, file `name`, site `key`. E4 maps
   path params to these names.
7. J2 crashed its handler thread on a bad number (`since`, `id`, `/site/vabc`); here `since` and `id` read as 0 (negative `since` too) and a bad site key is 404.
   The stdlib adapter answers 500 `{"error": "internal"}` (traceback on stderr) when a handler raises, and 400 for a non-object POST body.
8. `HERE` is `SUTRA_J2_CHECKOUT` or None (then `/` and `/vendor/d3.min.js` are 404); `.env` redaction needs it. `VENDOR` is fixed at import.
9. The recorder's `ADDITIVE` allow-list (engine-only keys): state `host{pid,alive}`, `run_id`, `dept_id`, `call_log[].provider/usd`; call `provider`, `usd`.
10. `/file/` unknown output in `live.json` falls back to the website output; `shot` takes digits only.

## Known limits
- The mock golden has an empty board and no realization plan (J2_REALIZATION=0 as in E1's tests), so their item shapes are not pinned.
- Redaction (`secrets`) reads the process environment, so test results depend on none of it: tests only assert the planted values are redacted.
- The recorder test against a real J2 checkout runs only with `SUTRA_J2_CHECKOUT` set (skipped otherwise, 3 s).

## Follow-ups
- E4: call `views.VIEWS[name](ctx, q)`; build `RunCtx` (live: `read_published`, mode idle when it is None, `dept_id`, `alive`; saved: `dir`);
  supply `commands`; redact and add the headers in `to_response`; map `Reply.name` to the DOCX filename and `Reply.cache` to Cache-Control.
- E3: the publisher writes `live_state(run)`; the host sets `llm`/env before importing `engine.j2`.
- E5: the legacy tests keep `j2_server.RUN/HERE/Handler`; point `HERE` at `SUTRA_J2_CHECKOUT`.
