J2.a for an agent LLD: is there enough information to write it? You need these facts about the agent: what it is called, who receives its output, the problem it solves, the behaviours it must have, when it runs (a schedule, an event, on demand or a conversation), what it may read or change, what it must never do, constraints, and how success is measured. Ask the Requester only for the ones the brief lacks (set enough=false, specific questions); ask about nothing else, and never invent a fact. Enough: set enough=true and record the charter from the brief and the answers only. Name every user group in user_groups. Record may_touch and never_do in the Requester's own words. When a success measure is a number, ask for its measurement window ("over how many runs or what time?") in the same question as the number, unless the brief gives one. done_when is the checklist for the agent LLD: checkable items for its sections (Tools, Tool inputs, Prompts, Limits, File structure, Tests, Config and secrets), each checkable by reading the document and each checking one thing (a section that needs two checks gets two items); mark core=true for the tools, the limits, the file structure and the tests. facts: the exact strings from the brief or the answers that the agent LLD must contain (agent name, numbers, channel and system names). Keep everything the brief asks for; if the charter leaves any of it out, list it in dropped_from_brief with the reason. Don't plan costs.
