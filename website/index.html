The Sutra canon

Documented like a system.
Shipped as a plugin.

Sutra is specified by its canon — 22 pillars, 10 primitives, 6 surfaces, 9 hardstops — the documentation of record for the whole operating system. The plugin is today’s shipping implementation of that spec inside Claude Code. The language below is the canon’s; the claims are what ships.

ROUTE
Ships today

One decision per input

Canon: every operator utterance is classified before any action fires — no silent-skip path. In the plugin today: Input Routing + Flow blocks classify every turn before any tool runs.

GATE
Ships today

Approval before consequence

Canon: execution pauses at approval-required steps until the founder decides. In the plugin today: pre-tool and stop hooks block edits until depth, blueprint, and review contracts are met.

RUN
Canon · runtime

Typed, verified execution

Canon: workflows fire step by step with typed execution logs, timeouts, and failure policy. Canon scope: Native runtime. The plugin’s analog is BLUEPRINT — per-step verification before the next step runs.

AUDIT
Ships today

Every decision on the record

Canon: every state transition persists as a replayable, typed event. In the plugin today: local JSONL logs record routing, depth, gate verdicts, and reviews — on your disk.

EMERGE
Canon · runtime

Patterns become process

Canon: repeated unmatched behavior is proposed back to the founder as a new workflow. Canon scope: Native runtime. The plugin’s analog is the feedback + learn loop.

TENANT
Canon · runtime

Boundaries fail closed

Canon: per-company isolation with private audit logs; crossing a boundary needs explicit delegation. Canon scope: Native runtime. The plugin’s analog is per-project boundary hooks.

Six of the canon’s 22 pillars, as they reach you through the plugin:

P0

Customer focus first

Every output is judged by whether the person reading it can understand it without extra explanation. Supersedes all other principles.

P1

Artifact-first

Nothing evaporates as chat — results land as typed, logged, reusable artifacts the system can consume again.

P11

Constrained problems

Context, constraints, and expected output are deliberately constructed for every AI call — no ambient state.

P15

Right effort

Before anything changes: state assumptions, prefer the simpler version, touch only what the request needs, verify the result.

P17

Architecture awareness

Survey the existing architecture before creating anything new, so additions fit the system instead of fragmenting it.

P18

Packaging before launch

Installation is part of the product: a couple of commands plus one activation step, hardened before anything launches.

And the hardstops — the lines the system will not cross:

HS-9
Ships today

Secrets never land in files

A pre-write hook denies any edit that would put key-shaped secret material into a committable file. Enforced in the plugin.

HS-2
Canon contract

Governance pays for itself

Canon contract: discipline machinery soft-targets ≤15% of turn tokens and hard-stops past 25%. The plugin’s governance is built to that bar.

HS-6
Canon contract

Failure never degrades silently

Canon contract: three governance-hook failures in one turn suspend the session until the founder clears it.

The founder

What is Sankalp actually doing?

The question everyone asks. Answered by behavior, not by title.

Sankalp Asawa runs one loop, daily: discover what Claude Code can newly do → understand it → fold it into Sutra — the plugin and the canon → keep Sutra a 1:1 map on top of Claude Code as it evolves. Every capability is dogfooded across his own portfolio — six owned products, two client projects, one holding company — before it ships to the fleet.

The goal: make running a company with AI an installable discipline — one command, and a founder gets the governance, memory, and operating loop that today only exist as hard-won practice. Short term: ship Native v1 — Sutra as a real engine rather than prompt discipline — while the plugin keeps proving the canon in production.

The method has a name: effectuation, a pattern Sarasvathy observed in expert entrepreneurs building under uncertainty. Start from means in hand — Claude Code fluency, active operating companies, client work — rather than a market forecast. Risk only affordable loss: services revenue funds the build. Partner with whoever commits: clients and fleet users shape the canon. Fold surprises into the product instead of defending a plan. One fixed point holds it together: the vision — an installable operating system for companies — stays steady while everything else can update weekly.

Deliberately not done yet: pricing, self-serve onboarding, revenue from the OS itself. That honesty is the point — the full question-by-question ledger lives in CLARITY.md.
