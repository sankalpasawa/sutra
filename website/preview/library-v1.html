Work item

Part

One goal with one check that flips. Everything a department does is one of these, whether you wrote it, a function proposed it, or an engine opened it on a run.

7parts in every one
4ways one is opened
0skills — on purpose
1

How one is made

four ways; the same record every time

You write it

In Now, or in the department. A goal and the check that ends it.

Opens at once. Nothing needs stamping to start your own work.

Priority proposes it

The function reads the done line against what is filed and names the gap.

Lands next on the list, with the reason it was ordered there.

An engine opens one

Every run opens its own, so a run can be counted rather than claimed.

Closes when the run's check flips, and links to what changed.

A chat opens one

Before a chat changes anything it opens one saying what it is about to do.

Closes on the check it declared, not on the chat saying it is done.

SettingWhat it decidesNow
Needs a checkWhether one can be opened without a check that flipsno
Names its filesWhether it must say which files it will touchyes
Closes byWhat may close one: the check, or a person saying sothe check
ReopensWhether a failed check reopens it instead of filing ityes
2

What one is made of

seven parts, and one thing that is not here
Its goalone line
The outcome somebody could see. Two outcomes means two work items.
Done whenthe check
The one check that flips. “the file exists and is not empty”, “the page answers on the live link”.
Who does itowner
A person, a chat or an engine. Always one, never a team.
What it touchesfiles
The folders and files it may change. Anything outside is refused while it is open.
Its refid
The short name everything else points at: the filed work, the asks, the run.
Where it isstate
Open, waiting on you, filed, or reopened because the check did not flip.
What it leftevidence
The check's own output, kept, so the close can be read back a month later.

No skills here. A work item says what is to be true when it is finished. It never says who knows how, or which skill does it. That is the engine's business, or the chat's, and keeping it out is what lets the same work item be done by a person today and an engine next month.
